# Roadmap: nuxt-bricks builder improvements

## Context

## 1. ProjectNavigation — компонент хидера с навигацией по заголовкам

**Цель:** Новый компонент для лендингов — навигация по якорям из Title-компонентов. Можно использовать sticky или статично.

**Файлы:**

- `playground/components/navigation/ProjectNavigation.vue` — **новый файл**, компонент навигации
- `playground/components/navigation/ProjectNavigation.brick.ts` — **новый файл**, story для билдера
- Модификация Title-компонента — добавить поддержку `anchorId` prop (якорь для навигации)

**Поведение:**

- Компонент автоматически собирает все Title-компоненты на странице через DOM (`querySelectorAll('[data-anchor-id]')`)
- Генерирует список ссылок-якорей
- Поддерживает sticky режим (через prop `sticky: boolean`)
- Scroll spy (через `IntersectionObserver`) подсвечивает текущую секцию
- Title компоненты получают prop `anchorId` — задаётся в билдере, рендерится как `id` атрибут на элементе

## 4. Рефакторинг под модульную архитектуру — ✅ выполнено (доменное деление в `src/runtime/modules/`, 2026-06)

**Цель:** Привести кодовую базу в соответствие с правилами SFC и best practices проекта. Разбить монолитные компоненты и файлы на изолированные сущности с чёткими зонами ответственности.

**Ключевые направления:**

1. **Разбивка на сущности** — выделить логические домены (canvas, sidebar, toolbar, modals, publishing) в самостоятельные модули с собственными компонентами, composables и типами
2. **Разделение логики согласно SFC / best practices** — controller-компоненты отдельно от presentation, бизнес-логика в composables, страницы содержат только `fetch*` методы и оркестрацию
3. **Лимит на размер файлов** — ни один файл не должен превышать ~500 строк (допустимо чуть больше для SFC с CSS Modules, но стремиться к минимуму)

**Критерии:**

- Компонент > 300 строк — кандидат на декомпозицию
- Composable > 500 строк — разбить на несколько composables по ответственности
- Store action-файлы — по одному действию на файл (уже частично сделано в `store/bricks/actions/`)
- Утилиты — группировка по домену, без «god-файлов»

**Верификация рефакторинга:**

- `npm run type-check` — без TS ошибок
- `npm run lint:fix` — без линтинг-ошибок
- Ручное тестирование всех затронутых фич в `/builder`
- Функциональная регрессия = 0
