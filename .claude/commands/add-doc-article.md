# Добавление статьи в документацию билдера

Ты — специализированный агент для добавления markdown-статей во встроенную документацию билдера.

## Инструкция пользователя

$ARGUMENTS

---

## Контекст

Встроенная документация — markdown-статьи в `builder/documentation/docs/guide/<locale>/`, рендерящиеся в модальном окне билдера. Статьи разложены по папкам локалей, и сейчас папка одна — `ru/`. Список статей фильтруется по активной локали интерфейса; у локали без своей папки статей нет вовсе, и модалка показывает заглушку «Скоро» (`bricks.docs.comingSoonTitle`) — русские статьи ей не подставляются.

Ключевые файлы (пути — от `src/runtime/modules/`):

- `builder/documentation/docs/guide/ru/` — markdown-статьи (папка на локаль)
- `src/runtime/public/docs/guide/images/` — публичные изображения (общие для локалей)
- `builder/documentation/composables/useDocumentationArticles.ts` — import.meta.glob, фильтр по локали, навигация
- `builder/documentation/composables/useMarkdownRenderer.ts` — markdown-it рендеринг
- `builder/documentation/components/TheBuilderDocumentationModal.vue` — UI модалки

## Алгоритм

### Шаг 1: Создать markdown-файл

Файл: `builder/documentation/docs/guide/ru/NN-slug.md`. Перевод на другой язык — папка этой локали с теми же `NN-slug`: появление папки само снимает заглушку.

- Числовой префикс `NN-` определяет порядок в навигации
- Посмотри существующие файлы в папке локали для выбора следующего номера

### Шаг 2: Формат статьи

```markdown
# Заголовок статьи

Первая строка — `# Заголовок` — извлекается автоматически для навигации.

## Секция

Текст статьи...

![Описание](./images/screenshot.webp)

[Ссылка на другую статью](./02-interface.md)
```

Абзац и пункт списка пишутся **одной строкой**, без ручных переносов. markdown-it
включён с `breaks: true`: каждый перенос внутри абзаца становится `<br>`, и текст,
перенесённый по ширине редактора, в модалке рвётся на куски. Prettier строки не
склеивает и не переносит.

Поля интерфейса называть так, как их видит пользователь. Если у свойства есть
`description`, панель показывает его вместо `label` — значит, в статье нужен текст
описания, а не короткая подпись.

### Шаг 3: Изображения

Помести в `src/runtime/public/docs/guide/images/` в формате WebP. Ссылайся как `./images/file.webp` (пути одинаковы для всех локалей). Скриншоты снимать на временных демо-данных, а не на данных владельца.

### Шаг 4: Кросс-ссылки

Ссылки вида `[текст](./02-interface.md)` перехватываются и открывают статью внутри модалки (без перезагрузки). Резолвятся **только внутри папки активной локали** — не ссылайся на статью, которой нет в той же папке (клик будет no-op).

Якорь работает только внутри статьи: `[текст](#заголовок)`. Id заголовка строит `createDocumentationHeadingSlug` (`builder/documentation/utils/documentationHeadingAnchors.ts`): текст в нижнем регистре, любая последовательность знаков кроме букв и цифр — один дефис, длина ограничена, повтор заголовка получает суффикс. «## Контекстное меню» → `#контекстное-меню`, но у заголовка со знаками препинания id не очевиден — не угадывай, а проверяй тестом из шага 5. Ссылку на якорь другой статьи (`./07-pages.md#версии`) санитайзер не пропускает и молча снимает `href`.

### Шаг 5: Тест корпуса

`test/builder/documentationSanitize.spec.ts` проверяет число статей (`articlePaths.length`) и что каждый якорь ведёт на существующий заголовок. Добавил или удалил статью — поправь число.

### Шаг 6: Hard refresh

После добавления нового файла потребуется `Cmd+Shift+R` из-за glob-кэша Vite.
