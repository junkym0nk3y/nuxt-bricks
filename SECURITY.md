# Политика безопасности

## Поддерживаемые версии

Проект в стадии `0.x`: исправления безопасности выходят только для последней
опубликованной минорной версии. Обновление до неё — условие получения
исправления.

| Версия  | Поддержка             |
| ------- | --------------------- |
| `0.0.x` | да, до выхода `0.1.0` |

## Как сообщить об уязвимости

**Не открывайте публичный issue** для ещё не раскрытой уязвимости: issue виден
всем, включая тех, кто попробует ей воспользоваться.

Сообщать через приватный канал GitHub — «Report a vulnerability» на вкладке
Security репозитория
([private vulnerability reporting](https://github.com/junkym0nk3y/nuxt-bricks/security/advisories/new)).
Канал приватный: переписка видна только вам и мейнтейнерам.

Что помогает разобраться быстрее:

- версия пакета, версия Nuxt и режимы `bricks.backend.mode` и `auth.mode`;
- шаги воспроизведения или proof of concept;
- что именно достигается — чтение чужих данных, обход роли, запись, отказ в
  обслуживании;
- готовность к раскрытию: с какого момента можно публиковать advisory.

## Чего ожидать

- Подтверждение получения — в течение 7 дней.
- Оценка и план исправления — в течение 14 дней после подтверждения.
- Исправление выходит вместе с GitHub Security Advisory; автор сообщения
  указывается в advisory, если не просил об обратном.

Проект поддерживает один мейнтейнер, поэтому сроки — намерение, а не SLA.

## Что в область не входит

- Конфигурация развёртывания у потребителя: политика бакета S3, публичный доступ
  к бакету, обратный прокси, сетевые правила, секреты в переменных окружения.
- Ограничения, объявленные в `README.md` в разделе «Границы поддерживаемого
  режима»: одна установка обслуживает одного владельца содержимого, лимиты
  частоты считаются на процесс.
- Уязвимости в зависимостях без пути эксплуатации через этот модуль — их место в
  обычном issue.
