# builder/publish/utils

| File                    | Purpose                                                                                                                                                                                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activeWrites.ts`       | The registry of the unfinished write operations of the current landing: handing out an id, closing one's own operation; the ban on a second write does not depend on `disabled` being painted                                                              |
| `currentPageWrite.ts`   | The orchestration of the store's writing actions: `publishPage` (creation + syncing the list), `publishCurrentPage` and `saveCurrentPageAsCopy`; they write into the shared state of the form only with the initiator's consent (DI, tested without Pinia) |
| `dates.ts`              | `formatPageVersionDateTime` — the date of a saved version (the moment the taken state was saved, not the moment of the snapshot); the dashboard's shared date format is `common/utils/bricks/dates.ts`                                                     |
| `draftSnapshots.ts`     | Comparing the snapshots of a draft (`isSnapshotEqual`, `isFormStateEqual`)                                                                                                                                                                                 |
| `draftStorage.ts`       | The builder's drafts in localStorage: the address keys (`…:draft:blog/post`), read/write/move with the outcome status, the probe of the storage's availability                                                                                             |
| `formState.ts`          | The default and normalized state of the publication form, the cache of the background color out of the app config                                                                                                                                          |
| `formValidation.ts`     | Validation of the publication form (`validatePublishFormState`) — the required fields, the formats, the routing, whether the page's address (the pair `urlPrefix + pagename`) and its editor's address are taken                                           |
| `keywords.ts`           | The boundary "a list of tags ↔ the `keywords` string": `parseKeywords` (split, trim, dedup) and `serializeKeywords`                                                                                                                                        |
| `pageLibraryWrite.ts`   | Writing pages outside the editor session: creating a draft with a given schema, duplicating by id (DI, tested without Pinia)                                                                                                                               |
| `pagesListWrite.ts`     | Local writes into the page list that go ahead of the server answer: the optimistic publication flag replaces the record with a new object, and that object identity is what tells one's own write from a fresh server answer                               |
| `pagesLoad.ts`          | The one-time load of the full pages list: tells "never loaded" apart from "loaded, empty", collapses parallel readers into one request, repeats a superseded response                                                                                      |
| `pagePayload.ts`        | Assembling the payload of a page's creation/update/meta PATCH (camelCase, snake_case is up to the call site)                                                                                                                                               |
| `pageVersionRestore.ts` | The orchestration of the store's `restorePageVersion`: the mandatory revision precondition, syncing the list, `toPageWriteError` on a conflict (DI, tested without Pinia)                                                                                  |
| `publishApi.ts`         | The API layer of the publish store: the CRUD requests of `/api/bricks` (+ the page versions) + normalizing the responses                                                                                                                                   |
| `requestErrors.ts`      | The errors of the requests: `RequestError` (the status + the conflict code), detecting a 409 revision conflict, `requirePageRevision` (the precondition of a rollback), `toPageWriteError` (a conflict → a refetch of the list + a localized text)         |
| `slugify.ts`            | Generating a pagename out of a page title (`slugifyPageTitle`) — transliteration, `[a-z0-9-]`; `generateCopyPagename` picks a free name for a copy within its own prefix                                                                                   |
| `validationSchema.ts`   | The pure factory of the yup schema of the meta fields (`createPublishValidationSchema`) — the sidebar plus the details panel                                                                                                                               |
| `deviceImpact.ts`       | `countDeviceOverrides` — how many overrides will disappear along with a deleted device (values rather than blocks: that is what the confirmation promises); `describeAbsorbedRange` — which neighbor gets the freed range                                  |
