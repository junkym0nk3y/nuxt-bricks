# persistence/server/utils

The shared server logic of the Nitro endpoints of `/api/bricks/**`.

| File                           | Purpose                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `handlerHelpers.ts`            | The shared helpers of the endpoints (parse → adapter → return); `requireNumericId`, the mappers of the domain refusals `toPageHttpError` (409 + `data.code`), `toMediaHttpError` (400 + `data.code`) and `toUsersHttpError` (409 + `data.code`)                                                                                                                            |
| `payloadPrimitives.ts`         | The base primitives of DTO validation: `invalid`, `assertKnownKeys`, the string and boolean checks                                                                                                                                                                                                                                                                         |
| `payloadValidation.ts`         | The server-first validation of the page DTOs: rejecting unknown keys, the types and bounds, `expectedRevision`                                                                                                                                                                                                                                                             |
| `pageAddressContext.ts`        | The context of the address check (`getConfiguredPageAddressContext`): the active prefixes of `bricks.routes` + whether the live render is on — it reads the runtimeConfig on behalf of the pure payload validators                                                                                                                                                         |
| `schemaPayloadValidation.ts`   | The iterative (non-recursive) depth/node/type guard over a `schema` ahead of `JSON.stringify`: `assertSchemaComplexity` + the limits on the depth, the node count and the bytes                                                                                                                                                                                            |
| `mediaPayloadValidation.ts`    | The server-first validation of the media DTOs (create/update, the category, the size)                                                                                                                                                                                                                                                                                      |
| `mediaCategoryRules.ts`        | The product rules of the media categories: `assertKnownMediaCategory` refuses an unknown slug before the expensive part of an upload (the dependency is a narrow Pick contract, so the rules are tested without a real Postgres)                                                                                                                                           |
| `mediaVariants.ts`             | The naming policy of the downscaled raster variants (`<uuid>-preview`, `<uuid>-mock`) and their presets: the names are in one place because the generation, the deletion and the import out of the bucket all read them                                                                                                                                                    |
| `storageErrors.ts`             | The domain errors of the storage layer (an occupied pagename, a revision mismatch, a missing media category) and the marker of a write refused for certain — a contract for custom adapters                                                                                                                                                                                |
| `authErrors.ts`                | The domain errors of the auth layer (`IAuthAdapter`): the last active administrator, a taken login                                                                                                                                                                                                                                                                         |
| `authUserRules.ts`             | The edge rules of the accounts as pure functions: the resulting state of an edit, the invariant "an active administrator exists", recognizing an edit that changes nothing                                                                                                                                                                                                 |
| `defaultAdmin.ts`              | The hash of the default password out of the seed of `migrations/0001_init.sql`: it is what tells the session request that an account's password is still the default one (the login and the password themselves are in `common/constants/auth.ts`)                                                                                                                         |
| `pageAddressGuard.ts`          | The address of a page under a partial update: merging the pair `urlPrefix + pagename` with the stored row (which it reads only when one field of the pair arrives) and the revision into the precondition when the caller passed none of its own                                                                                                                           |
| `pageUpdate.ts`                | The shared implementation of PUT/PATCH `/api/bricks/:id` (only the fields that arrived are updated)                                                                                                                                                                                                                                                                        |
| `pageVersionRestore.ts`        | The orchestration of POST `.../versions/:versionId/restore`: the version lookup + an updatePage with a mandatory `expectedRevision` (optimistic locking)                                                                                                                                                                                                                   |
| `templatePayloadValidation.ts` | The server-first validation of the template DTOs: unknown keys are rejected, and the schema with its complexity limits is reused whole out of the page validator (a template carries exactly the schema a page would accept)                                                                                                                                               |
| `templateThumbnails.ts`        | The lifecycle of a template's preview files: a file OF ITS OWN copied out of a page's frame (`template-<uuid>.webp`), because a link into the page's keep list would break with the page's very first save                                                                                                                                                                 |
| `requestBodyLimits.ts`         | The bounded reading of a body: a Content-Length pre-check + a stream limit, the JSON reader                                                                                                                                                                                                                                                                                |
| `multipartStream.ts`           | The entrance policy of a multipart form read as a stream: the ceilings of the body and of one part, the slot gate of forms read at the same time, the signal of a client that went away; `withMultipartFormData` collects the same form in memory for the endpoints that need the bytes anyway                                                                             |
| `multipartParts.ts`            | The bridge from the parser (an event emitter) to a loop over the parts: the queue, the one-shot bytes of a file part, the pump with a byte count and an idle bound                                                                                                                                                                                                         |
| `fileSignatures.ts`            | Sniffing the format by its magic bytes: `sniffImageFormat`/`sniffVideoFormat`/`looksLikeSvgMarkup` — the MIME and the extension are not to be trusted                                                                                                                                                                                                                      |
| `concurrencyGate.ts`           | The semaphore of the heavy operations (sharp decoding, the ingress of multipart forms): a concurrency limit + a bounded queue, an overflow → 503                                                                                                                                                                                                                           |
| `mediaConfig.ts`               | The media settings: `resolveMediaConfig` (the limits and the optimization out of the app config) and `resolveRequestedOptimization` (the bounds of the untrusted form fields over the config's defaults)                                                                                                                                                                   |
| `imageProcessing.ts`           | Working with the pixels: `optimizeImage` and `cropSquareImage` (sharp with `limitInputPixels`, under the shared semaphore), the sizes with the EXIF orientation taken into account, the extension and MIME helpers                                                                                                                                                         |
| `mediaFormats.ts`              | The MIME of a stored file by the head of its content: `resolveStoredMediaMime` (the signature decides, the name only tells apart the containers one signature covers)                                                                                                                                                                                                      |
| `mediaProcessing.ts`           | Validating the uploads (the type, the size, the signature) and optimizing them; a video is validated by the head of its content alone (`validateVideoUpload`) — its bytes never gather in memory                                                                                                                                                                           |
| `mediaImport.ts`               | Importing the files of the publication storage into the media database (the handler of POST /api/bricks/media/import): the type comes from the content, the whole bucket is read before the first write                                                                                                                                                                    |
| `mediaOrchestration.ts`        | The atomic pairs "a storage file + a database record": the upload of the files and the registration of the record as two steps (a picture arrives as a buffer, a video as a stream), compensation only under the guarantee that the write was refused (otherwise a retry), a file-first delete, the best-effort cleanup of the previews of a deleted page                  |
| `pageThumbnails.ts`            | The lifecycle of a page's preview files: a key unique per upload (`page-<id>-<uuid>.webp`), the best-effort sweep of the orphans under the page's prefix and the collection of the keep list after the frame is uploaded (the reads go "the page → its versions → the page" — otherwise a rollback in between carries the frame away)                                      |
| `bestEffortDelete.ts`          | `deleteFileBestEffort` — a deletion of a storage file that never throws; the caller says whether a failure is worth another attempt (`repeatOnFailure`): it is when the record pointing at the file is already gone and the object is public, and it is not when the caller is holding the error a person is waiting for. The repeats are bounded by a budget of their own |
| `avatarFiles.ts`               | The lifecycle of the profile photo files: a key unique per upload (`user-<id>-<uuid>.webp`) in a namespace of its own (not in the media library) and the best-effort sweep of an orphaned file                                                                                                                                                                             |
| `publicProjection.ts`          | The public projection of a published page for the public read model (with no editor fields, `revision` among them)                                                                                                                                                                                                                                                         |
