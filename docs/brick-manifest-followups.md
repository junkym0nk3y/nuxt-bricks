вырезанными спеками. После сокращения дефолт — заменить пофайловый список
описанием доменов, чтобы новый спек не требовал правки README.

## Условие для будущих правок резолва бриков

Не пункт, а требование к процессу — перенесено сюда из закрытого пункта про
границы контракта путей.

Любая правка на пути «схема → `brickPath` → карта загрузчиков → компонент»
проверяется published-страницей с настоящим brick-компонентом в **prod-сборке**
(`.output`, запущенный из постороннего cwd), а не только в dev. Компонент и его
проп из схемы обязаны попадать в сырой SSR-HTML без ошибок гидрации.

Причина, по которой dev не годится: async-компонент, чей лоадер отклонён, ведёт
себя в dev и prod по-разному — в dev Vue перебрасывает ошибку, и отличить её от
падения самой страницы нельзя. Один дефект этого класса (устаревший компонент в
схеме роняет published-страницу в 500) поэтому и описывался мягче, чем был.

Текущее состояние проверку проходит — она снималась 31 июля 2026.

**Альтернатива отклонена** (27 июля 2026, не начинать без явного пересмотра):
строить карту загрузчиков из резолвнутых каталогов компонентов, заменив
`import.meta.glob` на сгенерированный через `addTemplate` модуль. Выгода
обслуживает ровно те сценарии, которых нет ни в одном из трёх поддерживаемых
(playground, npm-модуль у потребителя, конвенциональные Nuxt 3 и 4), а размен
плохой: `import.meta.glob` разворачивает сам Vite одинаково в клиентском и в
SSR-бандле, тогда как импорт `#build/…` резолвится по-разному в dev и prod и
по-разному в клиентской и серверной сборке — при том что этот код лежит на
SSR-пути published-страниц. Возвращаться только если мягкий рестарт на
`add`/`unlink` окажется неприемлемо дорогим у потребителя или появится реальная
потребность в кастомных каталогах и слоях; начинать в обоих случаях со спайка на
два бинарных вопроса — резолвится ли `#build/…` из `dist/runtime/` установленного
пакета (проверять на `npm run smoke:pack`, не в playground) и находит ли
`getModulesByFile('virtual:nuxt:<dst>')` модуль шаблона в нашей конфигурации.
