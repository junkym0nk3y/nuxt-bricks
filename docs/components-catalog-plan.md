# Каталог компонентов в Figma: сведение на одну страницу + синк с кодом

Файл дизайн-системы: `fileKey: FsPQKxtsHrbJiyiyal9ZlR`
Рабочий процесс синка и конвенции файла — `docs/figma-sync-workflow.md`.

**Задача.** Сейчас компоненты разложены по 18 отдельным страницам Figma в секции
`——— COMPONENTS ———` (`Icon` … `Text Editor Toolbar`). Свести их в одну страницу
«🧩 Components» с секциями по группам кода и попутно привести каждый компонент к
текущему состоянию кода: макет местами отстал.

**Источник истины — код.** Файл построен методом code-to-design; при любом
расхождении правится макет, а не код.

---

## 1. Принятые решения

| Решение                                                               | Причина                                                                                                                                                                                                                       |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Одна страница, внутри **Figma-секции** по папкам `ui/`                | Секции сворачиваются и дают навигацию в левой панели вместо 18 страниц; группировка повторяет структуру кода, то есть каталог остаётся зеркалом `src/runtime/modules/ui/`                                                     |
| Не один большой фрейм-«постер»                                        | Фрейм пришлось бы перекраивать при каждом новом компоненте, а сеты внутри него выделяются через лишний уровень вложенности                                                                                                    |
| **Field Error** заводится отдельным компонентом                       | Решение владельца: полнота каталога важнее экономии. В коде используется в 8 файлах, иногда сам по себе                                                                                                                       |
| **Table Grid Picker** перепривязывается к реальному коду              | Пара «триггер 32×32 + попап» описывает `BricksTableGridPicker.vue` — вставку таблицы в TipTap, которой в коде нет (нет и `@tiptap/extension-table`). Механика жива у другого потребителя — редактора размера сетки блока Grid |
| Заводится секция **PROPERTY EDITORS**                                 | Решение владельца: в коде 8 редакторов свойств, в каталоге нет ни одного. Панель свойств рисуется ими, а не только UI-китом                                                                                                   |
| Аудит выполняется **внутри** этапов переезда, а не отдельным проходом | Переезд всё равно заставляет открыть каждый сет; сверка с кодом в тот же момент экономит повторное чтение и узла, и `.vue`                                                                                                    |
| Старые 18 страниц удаляются **последним** этапом                      | Пока каталог не собран целиком, страницы — единственная навигация по библиотеке                                                                                                                                               |

### Что переезд не ломает

Сет вариантов можно физически перенести на другую страницу — ключи компонентов не
меняются, поэтому инстансы на экранах (`31:5`, `69:5`, все концепт-страницы)
продолжают ссылаться на них и не отвязываются. Единственное, что меняется —
родитель узла. Это касается и переноса `Tab` с концепт-страницы в каталог.

### Контракты для новых компонентов

**Textarea** (`IBricksTextareaProps`): `value`, `label`, `disabled`,
`placeholder`, `maxLength`, `rows` (по умолчанию 3), `errorMessage`. Ось
`State` = `Default / Filled / Focus / Invalid / Disabled`; при `maxLength` —
счётчик. Ошибка рисуется вложенным `BricksFieldError`.

**Field Error** (`IBricksFieldErrorProps`): единственный проп `message`. Один
вариант: `<p>` цвета `danger-500`, `font-size: 1.2rem`, `line-height: 1.4`,
внешние отступы задаёт контекст. Появление — через `bricks-fade-fast`.

**Tab** (`IBricksTabBarProps`): `variant` (`segmented/outline/underline/ghost`),
`size` (`sm/md`), `tone` (`neutral/primary`), `radius` (`xs/sm`), плюс
`iconOnly`, `block`, `wrap` — пропы, а не оси.

## 4. Этапы

Этапы запускаются отдельными сессиями. Каждый самодостаточен: вход — этот
документ, выход — проверяемое состояние файла. Аудит входит в этап переезда.

## 5. Ограничения

- **Лимит Figma MCP на тарифе Pro** — ~10 вызовов/мин, 200/день. Инвентаризацию
  всех страниц снимает один скрипт через `PageNode.loadAsync()` без переключения
  страниц; переключать `setCurrentPageAsync` можно не чаще одного раза за вызов.
- **Красить только переменными.** Новый цвет — сначала в коллекцию Color (оба
  мода + Code syntax), затем в компонент.
- **Не отвязывать инстансы.** Правки вариантов — в самом сете.
- **Размеры кратны 2px** (1px = 0.1rem кода).
- **Никаких идентификаторов этапов** (`Э3` и подобных) в описаниях компонентов
  Figma, в коде и в сообщениях коммитов: спринт временный, а описание должно
  читаться без этого документа.

Замечания, всплывшие при съёме базлайна:

- Оба переезжающих узла лежат на концепт-страницах, а не в секции компонентов:
  `Tab` — на `330:2`, `Spacing Editor` — на `88:2`. После их переезда обе
  страницы остаются жить (там борды применения), удаляются только 18 страниц

- Нулевой счётчик — не повод считать компонент мёртвым: `Modal` `24:67`,
  `Toast` `21:22`, `Hex Input` `24:28` в макете нигде не инстанцированы, но в
  коде живы. `Table Grid Picker` (`26:108`, `26:109`) тоже 0 — перепривязка
  ничего не отвяжет.
- Все 33 узла из раздела 2 найдены; `getNodeByIdAsync` сработал после поштучного
  `page.loadAsync()` по всем 49 страницам, переключать текущую страницу для
  этого не требуется.

**Считать в два прохода — первый недосчитывает.** Числа выше исправлены
2026-08-04: изначально в них стояли `Button 41`, `Close Button 18`, `Tag 6`,
`Toolbar Button 3` и итог 539. Один и тот же скрипт, дважды подряд опросивший те
же узлы в одном запуске, вернул 539 и затем 552 — на третьем и четвёртом проходе
552 держалось. То есть после `page.loadAsync()` индекс инстансов дозаполняется
лениво, и первый `getInstancesAsync()` видит не всё: недосчитанные инстансы
лежали на тяжёлых страницах (`🖥 Builder`, `📄 Pages Manager`, `📝 Text Editor`).

Переезд здесь ни при чём: `Toolbar Button` вырос с 3 до 6, хотя его никто не
трогал — он всё ещё лежит на своей странице. Поэтому базлайн и сверка после
каждого этапа снимаются **вторым проходом**, а расхождение первого и второго
прохода — сигнал о ленивом индексе, а не о потерянных инстансах.

## Ревизия концепт-страниц (4 августа 2026)

Обе страницы-источника переезда удалены — решение владельца при разборе
концептов: борды применения на них описывали уже реализованные экраны и
дублировали `🖥 Builder` и `📄 Pages Manager`. Замечание выше о том, что
страницы «остаются жить», этим отменено.

- `88:2` «Spacing Editor» — удалена целиком, редактор отступов реализован. Вместе
  со страницей ушёл демо-фрейм «In context» `89:450`, который Э8 оставлял жить на
  ней: сам компонент `Spacing Editor` давно в каталоге, но его инстанс в демо
  удалён, поэтому счётчик инстансов этого узла уменьшился на единицу.
- `330:2` «Tab Bar» — удалена после того, как в каталог уехал не только сет
  `Tab` (`334:2`, секция BASE), но и четыре компонента `Tab Icon/*`. У
  `Tab Icon/device-desktop` 60 инстансов — внутри самих вариантов `Tab`, так что
  удаление страницы вместе с глифами отвязало бы весь сет. Глифы лежат в секции
  ICON рядом с `Icon` и `Layout Icon`.
- Тем же порядком спасены 9 компонентов `Layout Icon/*` с удалённой страницы
  «Components Sidebar (redesign)»: 43 инстанса на `🖥 Builder` и
  `🎯 Canvas Interaction`.

Правило, которое из этого следует: перед удалением любой страницы прогонять по
ней `findAllWithCriteria({ types: ['COMPONENT', 'COMPONENT_SET'] })` и
`getInstancesAsync()` вторым проходом — компоненты в этом файле живут не только
в каталоге, и «страница-концепт» может оказаться донором для библиотеки.

Подпись сета `Tab` переписана по `base/tabs/types.d.ts`: четыре стиля,
`groupLabel` вместо `ariaLabel`, обязательный `label`, проп `wrap`, семантика
`role="group"` + `aria-pressed` (reka `ToggleGroup`) вместо `tablist`.
