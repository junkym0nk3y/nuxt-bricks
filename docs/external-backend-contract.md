# Контракт external data backend

Контракт HTTP-ручек, которые обязан реализовать пользовательский backend при
`bricks.backend.mode = 'external'`. Потребители модуля не обязаны использовать
встроенную PostgreSQL-часть — достаточно реализовать описанную здесь структуру
ручек.

Модель разделения (см. `docs/backend-connection-modes-plan-2026-07-12.md`):
external backend хранит только **данные** — страницы, версии страниц и
media-метаданные. Файлы (S3), обработка изображений (sharp), thumbnail/media
proxy и все browser-facing `/api/bricks/**` остаются локальными ручками
nuxt-bricks. Браузер с external backend'ом напрямую не общается — CORS не
требуется.

Референс-реализация — fake backend nitro-смока:
`scripts/external-smoke-backend.mjs` (запуск: `npm run smoke:external`).

## Конфигурация

```typescript
export default defineNuxtConfig({
    modules: ['nuxt-bricks'],
    bricks: {
        backend: {
            mode: 'external',
            // ПОЛНЫЙ префикс до «корня» bricks-API вашего сервера —
            // сегмент «bricks» не зашит, монтируйте API где угодно
            url: process.env.BRICKS_BACKEND_URL, // например https://api.example.com/my-cms
            healthUrl: process.env.BRICKS_BACKEND_HEALTH_URL, // опционально
        },
        s3: {
            /* S3 нужен в обоих режимах — файлы всегда локальный pipeline */
        },
    },
});
```

| Env                              | Назначение                                                       |
| -------------------------------- | ---------------------------------------------------------------- |
| `NUXT_BRICKS_BACKEND_URL`        | Server-only base URL (runtime-override `backend.url`)            |
| `NUXT_BRICKS_BACKEND_TOKEN`      | Опциональный Bearer-токен server-to-server запросов (только env) |
| `NUXT_BRICKS_BACKEND_HEALTH_URL` | Readiness-эндпоинт (runtime-override `backend.healthUrl`)        |

Сам `mode` — build-time и через env НЕ переопределяется.

## Общие требования транспорта

- Все пути — **относительные от `backend.url`** (`{base}` ниже); соединение
  путей нормализует слэши (`joinURL`), trailing slash в `backend.url` не важен.
- Формат — JSON. Тела запросов (POST/PATCH) приходят в **camelCase** как есть.
  Ответы сервер может отдавать в snake_case или camelCase: адаптер нормализует
  **только top-level ключи** snake_case → camelCase; вложенные значения
  (включая `schema`) не трогаются.
- Даты — строки **ISO 8601** (`createdAt`, `updatedAt`, `uploadedAt`,
  `pageUpdatedAt`).
- **Аутентификация**: при заданном `NUXT_BRICKS_BACKEND_TOKEN` каждый запрос
  несёт `Authorization: Bearer <токен>`. Browser identity (cookie
  `bricks-session`, Basic-креды) НЕ пробрасывается — заголовки строятся с нуля.
- **Таймаут** — 10 с на запрос (`AbortSignal.timeout`); ответьте быстрее.
- **Редиректы запрещены** (`redirect: 'error'`): 3xx = ошибка запроса.
- Пустое тело / 204 трактуются как `null` (нормально для DELETE).

## Структура ручек

Зеркало локальной структуры `/api/bricks/**` относительно `{base}`:

| Метод HTTP | Путь                             | Операция                              | Особенности                                                                              |
| ---------- | -------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------- |
| GET        | `{base}`                         | Список страниц (сводки без `schema`)  | Массив `TBricksPageSummaryRow`                                                           |
| POST       | `{base}`                         | Создать страницу                      | 409 `PAGENAME_CONFLICT`                                                                  |
| GET        | `{base}/:id`                     | Страница по id (полная, со `schema`)  | 404 → «не найдено»                                                                       |
| PATCH      | `{base}/:id`                     | Частичное обновление страницы         | **только PATCH**; 409 `REVISION_CONFLICT`/`PAGENAME_CONFLICT`; инвариант версионирования |
| DELETE     | `{base}/:id`                     | Удалить страницу                      | 404 → «не найдено»                                                                       |
| GET        | `{base}/:id/versions`            | Сводки версий страницы (новые сверху) | Массив `IPageVersionSummary`                                                             |
| GET        | `{base}/:id/versions/:versionId` | Полный снапшот версии                 | Путь SSR превью версии; 404 → «не найдено» (в т.ч. чужая версия)                         |
| GET        | `{base}/public/pages/<адрес>`    | **Public lookup** по адресу страницы  | Горячий путь SSR; адрес — остаток пути; 404 для draft/несуществующей                     |
| GET        | `{base}/media`                   | Список media-метаданных               | Массив либо envelope `{ items: [...] }`                                                  |
| POST       | `{base}/media`                   | Регистрация media-метаданных          | **Server-to-server-only**; идемпотентна по `url`; 400 `UNKNOWN_MEDIA_CATEGORY`           |
| PATCH      | `{base}/media/:id`               | Обновление метаданных                 | Поля: `filename`, `alt`, `category` (частично); 400 `UNKNOWN_MEDIA_CATEGORY`             |
| DELETE     | `{base}/media/:id`               | Удалить media-запись                  | Только метаданные — файл удаляет nuxt-bricks                                             |
| GET        | `{base}/media/categories`        | Список категорий медиатеки            | Массив либо envelope `{ items: [...] }`                                                  |
| POST       | `{base}/media/categories`        | Создать категорию                     | Идемпотентна по `slug`                                                                   |
| DELETE     | `{base}/media/categories/:slug`  | Удалить категорию, сняв её с файлов   | **Обе половины атомарны**; отвечать JSON, не 204                                         |
| GET        | `{base}/templates`               | Список шаблонов (сводки)              | Массив либо envelope `{ items: [...] }`; с `blocksCount`, новые сверху                   |
| POST       | `{base}/templates`               | Создать шаблон                        | 409 `TEMPLATE_NAME_CONFLICT`; идемпотентности НЕТ                                        |
| GET        | `{base}/templates/:id`           | Шаблон по id (полный, со `schema`)    | 404 → «не найдено»                                                                       |
| PATCH      | `{base}/templates/:id`           | Правка подписи шаблона                | Поля: `name`, `description`; 409 `TEMPLATE_NAME_CONFLICT`; 404 → «не найдено»            |
| DELETE     | `{base}/templates/:id`           | Удалить шаблон                        | Отвечать `{ thumbnail_url }` удалённой записи; 404 → «не найдено»                        |

### Ошибки

- **404** — контрактное «не найдено»: адаптер превращает в `null`
  (get-операции) или `false` (delete). Ручки nuxt-bricks вернут браузеру 404.
- **409** — конфликт с машиночитаемым кодом в JSON-теле по формату
  `{ "data": { "code": "..." } }` (как локальный `toPageHttpError`; top-level
  `"code"` тоже принимается). Распознаются только точные коды:
    - `PAGENAME_CONFLICT` — адрес страницы (`urlPrefix` + `pagename`) занят
      (POST страницы; PATCH при смене любой половины пары). Код исторический:
      имя оставлено ради совместимости внешних backend'ов;
    - `REVISION_CONFLICT` — не совпала `expectedRevision` (PATCH страницы);
    - `TEMPLATE_NAME_CONFLICT` — имя шаблона занято (POST шаблона; PATCH при
      смене имени). Клиент подставляет подсказку под поле имени формы, поэтому
      generic-409 здесь означал бы общий текст ошибки вместо неё.

    409 без кода или с незнакомым кодом — generic-ошибка (браузер получит 500 с
    errorId), доменной интерпретации не будет.

- **400** — доменный отказ записи медиа, тоже только по точному коду:
    - `UNKNOWN_MEDIA_CATEGORY` — категории с переданным slug'ом не существует
      (`POST {base}/media`, `PATCH {base}/media/:id`). Браузер получит 400 с тем
      же кодом и локализованный текст.

    400 без кода или с незнакомым кодом — generic-ошибка: выдавать произвольную
    валидацию за отсутствующую категорию значило бы соврать пользователю.

- Прочие статусы (401, 5xx, …) — generic-ошибка; upstream-статус браузеру НЕ
  пробрасывается.

### Гарантия исхода записи

Загрузка медиа состоит из двух половин: файл кладётся в бакет (это делает
nuxt-bricks сам), метаданные регистрируются у вас. Если регистрация не удалась,
удалять уже загруженный файл безопасно ТОЛЬКО когда точно известно, что записи
не появилось. Поэтому ответы делятся на два класса:

- **отказ гарантирован** — 400 с контрактным кодом выше: получив такой ответ,
  nuxt-bricks считает, что строка не создана, и удаляет файл из бакета. Отвечайте
  так, только если запись действительно не зафиксирована;
- **исход неизвестен** — таймаут, обрыв соединения, любой 5xx: ответ мог не
  доехать уже после коммита. nuxt-bricks файлы НЕ удаляет и один раз повторяет
  `POST {base}/media` с тем же `url` — отсюда требование идемпотентности ниже.
  Не помог и повтор — файлы остаются в бакете, их адреса уходят в server-лог.

### Страницы

Полная строка страницы (`IBricksPageRow`) — обязательные поля:

| Поле              | Тип                      | Примечание                                                                                     |
| ----------------- | ------------------------ | ---------------------------------------------------------------------------------------------- |
| `id`              | number                   |                                                                                                |
| `pagename`        | string                   | Уникален В ПРЕДЕЛАХ своего `urlPrefix`                                                         |
| `title`           | string \| null           |                                                                                                |
| `description`     | string \| null           |                                                                                                |
| `keywords`        | string \| null           |                                                                                                |
| `backgroundColor` | string \| null           |                                                                                                |
| `layout`          | string \| null           |                                                                                                |
| `socialImage`     | string \| null           |                                                                                                |
| `urlPrefix`       | string \| null           | Вместе с `pagename` — адрес страницы                                                           |
| `subdomain`       | string \| null           |                                                                                                |
| `thumbnailUrl`    | string \| null           | Машинное поле (пишется PATCH'ем)                                                               |
| `viewportConfig`  | array \| null            | Набор устройств страницы; хранить как есть (JSONB-семантика), `null` — наследует набор проекта |
| `schema`          | object (`IBricksSchema`) | Хранить как есть (JSONB-семантика)                                                             |
| `published`       | boolean                  |                                                                                                |
| `revision`        | number                   | Монотонный счётчик изменений строки                                                            |
| `createdAt`       | string (ISO 8601)        |                                                                                                |
| `updatedAt`       | string (ISO 8601)        |                                                                                                |

- `GET {base}` отдаёт сводки — те же поля **без `schema`**
  (`TBricksPageSummaryRow`). Полная строка — только point-lookup.
- `POST {base}` принимает `ICreatePagePayload` (`pagename`, `schema`,
  опциональные meta-поля, `published?`); сервер генерирует `id`, `revision`,
  даты.
- `PATCH {base}/:id` принимает `IUpdatePagePayload` — **partial**-семантика:
  обновлять только присланные поля. Поле `expectedRevision` — precondition
  optimistic locking, НЕ записываемое: при несовпадении с текущей `revision`
  ответить 409 `REVISION_CONFLICT`, ничего не меняя; без поля — запись без
  precondition (last-write-wins). Каждое успешное изменение инкрементирует
  `revision`.

**Инвариант версионирования** (обязанность external-сервера, автоматически не
проверяется): если в PATCH-payload присутствует `schema` либо `viewportConfig`
(обе — части версионируемого состояния: ключи `props.responsive` в схеме
относятся к набору устройств, и правка одного набора без снимка делает смену
топологии невосстановимой) и лимит версий больше
нуля, сервер обязан атомарно снапшотить ПРЕЖНЮЮ строку в историю версий и
обрезать (prune) историю страницы до лимита. Лимит — ваша конфигурация
(builtin использует `bricks.versionsLimit`).

Снапшот обязан копировать и `thumbnailUrl` прежней строки — галерея версий в
дашборде показывает превью каждого сохранённого состояния. Копируется именно
значение на момент снапшота: снимок канваса приезжает отдельным PATCH'ем ПОСЛЕ
сохранения, поэтому `thumbnailUrl` страницы в этот момент — кадр того
состояния, которое снапшот и уносит в историю. Заполнять версию снимком,
пришедшим после неё, нельзя: он показывает уже новое содержимое.

Версии:

- `IPageVersionSummary`: `id`, `pageId`, `thumbnailUrl` (string | null),
  `pageUpdatedAt` (updated_at исходной строки на момент снапшота, string | null),
  `createdAt`.
- `IPageVersion` (полный снапшот): summary + meta-поля страницы + `viewportConfig`,
  `schema`, `published`.

`viewportConfig` обязан входить и в снапшот версии, и в её восстановление: ключи
`props.responsive` в схеме относятся к тому набору устройств, при котором её
сняли. Откат схемы без набора дал бы страницу, где переопределения блоков
указывают на ступени, которых у неё нет.

`pageUpdatedAt` обязан быть и в сводке, а не только в полном снапшоте: даты
означают разное. `createdAt` — момент снапшота, то есть момент, когда состояние
**вытеснили**; `pageUpdatedAt` — момент, когда его **сохранили**. Пользователю в
галерее версий показывают вторую, иначе кадр подписывается временем следующего
сохранения (расхождение доходит до минут).

`thumbnailUrl` версии — обычный URL файла в хранилище публикации; сами файлы
загружает и убирает nuxt-bricks (ключ уникален на загрузку, сироты чистятся по
префиксу страницы). От backend требуется только хранить и отдавать значение.

### Public lookup (горячий путь)

`GET {base}/public/pages/<адрес>` вызывается при SSR **каждого визита**
published-страницы — поэтому lookup по адресу обязан быть точечным
(list+find на каждый визит недопустим). Требования:

- адрес приходит остатком пути: `…/public/pages/blog/post` — это
  `urlPrefix: "blog"`, `pagename: "post"`, а `…/public/pages/post` —
  `urlPrefix: null`. Сегменты не URL-кодируются целиком: разделитель `/`
  остаётся разделителем;
- искать по ПАРЕ, а не по одному имени, и считать отсутствие префикса
  значением: `/post` не должен находиться по адресу `/blog/post` и наоборот.
  Иначе одноимённые страницы под разными префиксами вернут произвольную из
  себя, и посетитель увидит чужую страницу под своим URL;
- отдавать страницу только если `published: true`; draft и несуществующая —
  404;
- формат — публичная проекция: поля `IBricksPageRow` (включая `viewportConfig` —
  он задаёт пороги media-query опубликованной страницы) **без** `thumbnailUrl` и
  `revision` (можно отдавать и полную строку — лишние поля не мешают);
- сегмент `public` — имя пути в структуре, а не требование открытого доступа:
  запросы приходят server-to-server с тем же Bearer.

Зазор проекции адаптер закрывает синтезом `thumbnailUrl: null, revision: 0,
published: true` — единственный вызывающий сразу применяет
`toPublicPageProjection`, отбрасывающую эти поля.

### Media

External backend хранит только **метаданные** (`IMediaItem`); binary живёт в
S3 и загружается локальным pipeline'ом nuxt-bricks (валидация → sharp/санитизация
SVG → S3 → регистрация метаданных).

`IMediaItem` — обязательные поля:

| Поле           | Тип               | Примечание                                  |
| -------------- | ----------------- | ------------------------------------------- |
| `id`           | number            |                                             |
| `url`          | string            | **Уникален** — ключ идемпотентности         |
| `filename`     | string            |                                             |
| `alt`          | string            | Пустая строка, если не задан                |
| `size`         | number            | Байты                                       |
| `uploadedAt`   | string (ISO 8601) |                                             |
| `mimeType`     | string            |                                             |
| `category`     | string \| null    | Slug существующей категории; null — без неё |
| `thumbnailUrl` | string?           | Опционально                                 |
| `svgContent`   | string \| null    | Санитизированный inline SVG (для SVG-медиа) |
| `width`        | number \| null    | Пиксельная ширина растра; null — неизвестна |
| `height`       | number \| null    | Пиксельная высота растра; null — неизвестна |
| `previewUrl`   | string \| null    | Вариант ~480px для постепенной загрузки     |
| `mockUrl`      | string \| null    | Вариант ~32px для постепенной загрузки      |

`category` **обязана присутствовать** и в ответе, и в теле `POST {base}/media`:
её значение — slug существующей категории либо `null` (файл без категории; он
виден только в фильтре «Все»). Ключ приходит всегда, даже когда категории нет:
browser-facing multipart без категории nuxt-bricks нормализует в `null` **до**
server-to-server запроса. В `PATCH {base}/media/:id` поле, наоборот, опционально —
отсутствие ключа означает «категорию не менять», `null` — «снять категорию».

`width`/`height`/`previewUrl`/`mockUrl` **обязаны присутствовать в ответе** (хотя
бы как `null`). Их отсутствие адаптер трактует как `null` и молча отключает
постепенную загрузку: потребитель покажет полный файл сразу, а раскладка
перестанет держать место под картинку до её загрузки.

- `GET {base}/media` — плоский массив либо envelope `{ items: [...] }`.
- `POST {base}/media` — JSON `{ url, filename, size, mimeType, category, alt?,
svgContent?, width?, height?, previewUrl?, mockUrl?, uploadedAt? }`; сервер
  генерирует `id` (и `uploadedAt`, если не прислан). **Никакого
  multipart/binary**. Ручка — server-to-server-only: браузерного аналога у
  nuxt-bricks нет (регистрация метаданных отдельно от файла из браузера
  недоступна — есть только `POST /api/bricks/media/upload`, который заливает
  файл и регистрирует запись одним запросом), поэтому принимайте её только с
  вашим Bearer-токеном.
- **Идемпотентность по `url`**: повторная регистрация того же `url` (гонка
  импорта, ретрай, повтор после неизвестного исхода) обязана вернуть
  существующую запись — не падать и не создавать дубликат. Ответ 409 адаптер
  дополнительно разруливает повторным чтением списка по `url`, но полагаться
  стоит на серверную идемпотентность. Существующая запись возвращается **до**
  проверки полей payload'а: категорию из первой попытки могли удалить, и
  отвечать на повтор `UNKNOWN_MEDIA_CATEGORY` вместо уже созданной строки
  нельзя.
- **Существование категории проверяется атомарно с записью** (внешним ключом или
  той же транзакцией): ненулевая `category`, которой нет в момент записи, —
  `400 UNKNOWN_MEDIA_CATEGORY`. Отдельной проверкой «до» гонку с удалением
  категории не закрыть, а её результат обязан быть внятным: nuxt-bricks делает
  свою раннюю проверку только чтобы не платить за оптимизацию и заливку файла.
- `DELETE {base}/media/:id` удаляет только метаданные: file-first порядок
  (сначала S3-объект, потом запись) обеспечивает локальный handler; отказ
  регистрации при upload компенсируется удалением S3-объекта тоже локально, но
  ТОЛЬКО под гарантию отказа (см. «Гарантия исхода записи» выше) — при
  неизвестном исходе файлы сохраняются.

### Категории медиатеки

Набор категорий — данные, а не константа: nuxt-bricks своей копии списка не
держит и целиком полагается на эти три ручки.

`IMediaCategory` — обязательные поля:

| Поле        | Тип    | Примечание                                                       |
| ----------- | ------ | ---------------------------------------------------------------- |
| `id`        | number |                                                                  |
| `slug`      | string | **Уникален**; то, что лежит в `bricks_media.category`, ≤50 симв. |
| `label`     | string | Подпись — введённый пользователем текст, не ключ i18n            |
| `sortOrder` | number | Порядок показа в дорожке категорий                               |

- `GET {base}/media/categories` — плоский массив либо envelope `{ items: [...] }`,
  в порядке показа.
- `POST {base}/media/categories` — JSON `{ slug, label }`; **slug считает
  nuxt-bricks** (транслитерация подписи), сервер его не переопределяет.
  **Идемпотентна по `slug`**: повтор обязан вернуть существующую запись, а не
  падать и не создавать дубликат. 409 адаптер дополнительно разруливает повторным
  чтением списка, но полагаться стоит на серверную идемпотентность.
- `DELETE {base}/media/categories/:slug` — удаляет категорию, сняв её со своих
  файлов (`category` у них становится `null`).
    - **Обе половины обязаны быть атомарны.** Локальная сторона обернуть их в
      транзакцию не может, а два HTTP-вызова оставили бы окно, в котором категория
      с файлов уже снята, а сама категория осталась.
    - Ответ — **JSON `{ clearedCount: number }`**. `204 No Content` не подходит:
      адаптер разбирает тело как объект и на пустом ответе бросает ошибку формата.
      Число показывается пользователю — «удалили категорию» и «12 файлов остались
      без категории» это разные события.
    - 404 → адаптер вернёт `null`, ручка ответит браузеру 404.
- **Неудаляемых категорий нет.** Предустановленного набора тоже: категории целиком
  заводит пользователь, приёмника для осиротевших файлов не существует. Сервер не
  вправе отклонять удаление «своих» категорий — nuxt-bricks такого ответа не
  ожидает и покажет его пользователю отказом.

### Шаблоны страниц

Шаблон — отпечаток готовой страницы: её схема и оформление под своим именем.
Связи с созданными из него страницами нет, поэтому и версий у шаблона нет.

Полная строка (`IBricksTemplateRow`) — обязательные поля:

| Поле           | Тип               | Примечание                                                       |
| -------------- | ----------------- | ---------------------------------------------------------------- |
| `id`           | number            |                                                                  |
| `name`         | string            | **Уникален** — им шаблон опознают в списке и в выборе источника  |
| `description`  | string \| null    |                                                                  |
| `thumbnailUrl` | string \| null    | Файл превью шаблона; `null` — карточка рисует плейсхолдер        |
| `schema`       | object            | Тот же формат, что у страницы                                    |
| `pageMeta`     | object            | `{ layout, backgroundColor, viewportConfig }` — все три nullable |
| `createdAt`    | string (ISO 8601) |                                                                  |
| `updatedAt`    | string (ISO 8601) |                                                                  |

Сводка списка (`TBricksTemplateSummary`) — та же строка **без** `schema` и
`pageMeta`, зато с `blocksCount` (число блоков схемы). Считать его обязан
backend: схемы в сводке нет, и восстановить число адаптеру нечем. Порядок списка
— по дате СОЗДАНИЯ вниз: правка подписи не должна перебрасывать карточку в начало
сетки.

- `POST {base}/templates` — JSON `{ name, description, schema, pageMeta,
thumbnailUrl }`. `thumbnailUrl` здесь — уже собственный файл шаблона: копию кадра
  страницы делает nuxt-bricks (кадры страницы живут по её keep-list'у, и ссылка
  из шаблона той уборке невидима). **Идемпотентности нет и быть не должно**:
  повторный POST с тем же именем — вторая попытка человека, и молчаливый ответ
  «уже есть» выдал бы чужой шаблон за только что сохранённый; отвечайте
  `409 TEMPLATE_NAME_CONFLICT`.
- `PATCH {base}/templates/:id` — только `name` и `description`. Содержимое
  отпечатка не обновляется: «обновить шаблон текущей страницей» потребовало бы
  версий шаблона и разрешения конфликтов.
- `DELETE {base}/templates/:id` — отвечайте JSON со `thumbnail_url` удалённой
  записи (или `null`): файлы превью остаются локальными и в external-режиме, и
  без этого поля nuxt-bricks не сможет убрать осиротевший объект из бакета.
  Ответ 204 удалением не считается ошибкой, но файл в этом случае остаётся.

### Readiness

`GET /api/bricks/health/ready` nuxt-bricks проверяет external backend:
`GET` по `backend.healthUrl`, а если он не задан — дешёвая проба `GET {base}`
(контрактный список страниц). Готовность — только 2xx; таймаут 5 с на probe.
