# Редактирование шаблона в редакторе

## Цель

На карточке шаблона в разделе «Шаблоны» дашборда есть кнопка «Редактировать». Она
открывает шаблон в редакторе билдера: тот же канвас, библиотека, панель свойств и
медиатека. В тулбаре вместо меню Save одна кнопка «Сохранить шаблон», без «копии» и
прочих вариантов. Сохранение перезаписывает содержимое шаблона и снимает ему новое
превью.

## Объём первой версии (решение владельца)

- Без черновиков в браузере: несохранённые правки пропадают при закрытии вкладки.
- Без защиты от одновременной правки: сохраняется последнее.
- Редактировать могут editor и admin (как создавать и переименовывать шаблоны); viewer
  кнопку не видит, а прямой адрес открывает шаблон без сохранения, как редактор страниц.

## Что было до этого

Шаблон считался неизменяемым снимком страницы: `PATCH /api/bricks/templates/:id` менял
только название и описание. Это решение записано в типах (`common/types/templates.d.ts`),
в обработчике PATCH, в карточке шаблона и в контракте внешнего бэкенда; всё это
переписывается.

## Сервер

1. `PATCH /api/bricks/templates/:id` принимает ещё `schema` и `pageMeta` (те же валидаторы,
   что при создании). Адаптерный payload получает и `thumbnailUrl` — его пишет только
   эндпоинт превью, из тела запроса клиента он не принимается.
2. Postgres: `schema`, `pageMeta`, `thumbnailUrl` в списке обновляемых полей, `pageMeta`
   сериализуется в JSONB.
3. `POST /api/bricks/templates/:id/thumbnail` — снимок канваса (multipart `file`), тот же
   приём, что у превью страницы: лимит частоты, потолок размера, проверка сигнатуры,
   перекодирование в webp ≤480 px. Ключ — `buildTemplateThumbnailKey`, старый файл
   удаляется после записи строки (`discardTemplateThumbnail`). Общие части приёма
   вынесены из `s3-page-thumbnail.post.ts`.
4. Контракт внешнего бэкенда (`docs/external-backend-contract.md`): PATCH шаблона
   принимает новые поля.

## Клиент

1. Маршрут `<builderPrefix>/bricks-template/:templateId(\d+)` (имя
   `bricks-builder-template`) — свой корень `builder/app/pages/template.vue`, по образцу
   `[pagename].vue`, но без страничных частей (адрес, черновики, выбор страницы,
   публикация, превью). Статический сегмент выигрывает у маршрута страницы.
2. Общая часть рабочего места вынесена из `useBuilderPage` в `useBuilderWorkspace`
   (устройства, стили, медиатека, документация, библиотека, сброс по токену сессии);
   `useBuilderPage` = страничная часть + рабочее место, единственный `await` последним.
3. `useBuilderTemplateSession` — загрузка шаблона по id в сторы (схема, layout, фон,
   устройства через форму публикации), состояние загрузки и ошибки, повтор.
4. `useBuilderTemplateWrite` — «Сохранить шаблон»: PATCH содержимого, обновление карточки
   в кэше дашборда, затем снимок превью (best-effort, как у страниц).
5. Снимок канваса вынесен из `usePageThumbnail` в общий захват (`Blob`), загрузка у
   страницы и шаблона своя.
6. Тулбар: режим `template` — название шаблона текстом, без превью и выбора страницы,
   одна кнопка «Сохранить шаблон».
7. Сайдбар: настройки в режиме шаблона — layout, устройства, фон, навигация; без
   публикации, адреса, SEO и картинки для соцсетей. Окно устройств вынесено из слота SEO.
8. Карточка шаблона: кнопка «Редактировать» на превью рядом с «Создать страницу».
9. Выход из редактора шаблона ведёт в раздел «Шаблоны» дашборда через
   `?section=templates`: дашборд открывает раздел по нему и сразу снимает query. Путей
   три — логотип (в новой вкладке, как у страниц), экран ошибки загрузки и кнопка «Назад»
   браузера: перед переходом в редактор раздел помечает свою запись истории тем же query.

## Проверки

- Серверная валидация PATCH с содержимым, эндпоинт превью шаблона.
- Сессия и сохранение шаблона (загрузка в сторы, PATCH, обновление кэша, превью).
- Живой прогон: открыть шаблон, поправить блок, сохранить, создать из шаблона страницу и
  увидеть правку; карточка с новым превью; страницы редактируются как раньше.
- После реализации — синк макета (📦 Templates, 🖥 Builder) по `docs/figma-sync-workflow.md`.
