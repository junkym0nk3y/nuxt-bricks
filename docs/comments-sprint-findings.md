# Спринт комментариев: находки

Список находок ревью по спринту `comments-sprint.md`. **Правки логики в этом спринте
не делаются** — здесь только регистрация. Исключение одно: разъехавшийся с кодом
комментарий правится текстом сразу, потому что это и есть работа с комментарием.

Категории: разъехавшийся комментарий, KISS/DRY, мёртвый код, нарушение границ
домена, кандидат на оптимизацию, i18n-долг.

Ground truth для утверждений о границах — `.dependency-cruiser.cjs`.

## Этап 0 — эталон и гейт

### 0.1 Шапка `apiRequestPolicy.ts` называла точку применения политики неверно

**Файл:** `src/runtime/modules/common/utils/apiRequestPolicy.ts:1-12`
**Категория:** разъехавшийся комментарий
**Статус:** текст исправлен в этапе 0

Шапка утверждала, что все три транспорта применяют политику «в `onRequest`».
Фактически ни один этого не делает: `applyApiRequestTimeout` вызывается в
собственной обёртке запроса каждого клиента — `useApiClient.ts:219`,
`usePublicPageClient.ts:112`, `useDataSourceClient.ts:114`. Более того,
`useApiClient.ts:191` отдельным блоком объясняет, **почему** не в `onRequest`:
опознать срабатывание потолка можно только зная сигнал. А `useApiClient.ts:154-157`
называет вторую причину: ofetch собирает опции как `{ ...defaults, ...call }`, и
`onRequest` вызывающего заменяет хук клиента целиком.

В переводе тезис заменён на фактический («внутри своей обёртки запроса») со ссылкой
на `useApiClient.ts` вместо копии рационала.

### 0.2 Тот же неверный тезис в `useDataSourceClient`

**Файл:** `src/runtime/modules/render/composables/useDataSourceClient.ts:35`
**Категория:** разъехавшийся комментарий
**Статус:** открыто, править в этапе 5

### 0.3 Число из другого слоя копией в прозе

**Файл:** `src/runtime/modules/persistence/server/utils/requestBodyLimits.ts`
(блок над `INFLIGHT_MULTIPART_BUDGET_BYTES`)
**Категория:** кандидат на переформулировку
**Статус:** открыто

Комментарий обосновывает бюджет через «тридцать загрузок в минуту». Значение верное
(`UPLOADS_PER_MINUTE = 30`), но живёт в другом слое —
`src/runtime/server/api/bricks/media/upload.post.ts:44`, и на 20 у аватарок
(`users/me/avatar.post.ts:55`) уже не сходится. Правка константы обесценит прозу
молча. Кандидат: назвать константу вместо числа либо сказать «лимит ручки»
без цифры. Перевод пока сохраняет число как есть — это не дрейф, а риск дрейфа.

### 0.4 Пустой `<script setup>` в одну строку терялся парсером целиком

**Файл:** `scripts/comment-lines.mjs` (`splitSfcBlocks`), проявление —
`src/runtime/layouts/bricks.vue:7`
**Категория:** дефект инструмента спринта
**Статус:** исправлено в этапе 0, покрыто спекой

Разбивка SFC требовала, чтобы открывающий тег заканчивал строку. У
`<script setup lang="ts"></script>` он её не заканчивает, и блок не находился вовсе.
Сегодня последствий нет — блок пуст, — но для гейта «молча пропустить целую секцию»
неверный режим отказа. Исправлено: закрытие на той же строке распознаётся.

### 0.5 `--diff` пропускал правку кода на строке с хвостовым комментарием

**Файл:** `scripts/comment-language-check.mjs` (`verifyDiff`)
**Категория:** дефект инструмента спринта
**Статус:** исправлено в этапе 0, покрыто спекой и мутацией
**Источник:** ревью Codex, подтверждено мутацией

Первая версия режима спрашивала «является ли изменённая строка строкой
комментария». Строка с хвостовым комментарием ей является, поэтому правка
`credentials: 'include'` → `'omit'` на строке
`useApiClient.ts:114` проверку **проходила** — то есть проверка не выполняла
единственного, ради чего существует. Проверено мутацией: до правки `exit=0`.

Исправлено сменой принципа: файл проецируется на свой код (символы комментариев
забиваются пробелами, пустые строки отбрасываются, остальные обрезаются), и
проекции двух ревизий обязаны совпасть. Побочно упростило код — разбор
unified diff с отслеживанием номеров строк удалён целиком, хватает
`git diff --name-status`.

### 0.6 Русские имена кейсов `it.each` не считались

**Файл:** `scripts/comment-lines.mjs` (`collectTestTitles`)
**Категория:** дефект инструмента спринта
**Статус:** исправлено в этапе 0, покрыто спекой
**Источник:** ревью Codex, подтверждено

У табличных кейсов заголовок — первый аргумент **второго** вызова
(`it.each([403, 404])('отказ %i ...', ...)`), и регексп его не видел. Недосчёт —
26 имён из 2022 (счётчик показывал 1996). Исправлено разбором: аргумент таблицы
перешагивается сопоставлением скобок, заголовок читается после него. Форма с
tagged-template (`it.each` и сразу обратная кавычка) не распознаётся — в
репозитории её нет, ограничение записано в докстринге.

### 0.7 Файлы без расширения не попадали в скан

**Файл:** `scripts/comment-sprint-areas.mjs`
**Категория:** дефект инструмента спринта
**Статус:** исправлено в этапе 0
**Источник:** ревью Codex, подтверждено

### 0.11 Проекция считала Markdown кодом — этап 20 нельзя было подтвердить

### 0.12 Эвристика regexp/деление теряла комментарий после постфиксного оператора

**Файл:** `scripts/comment-scanner.mjs` (`slashStartsRegex`)
**Категория:** дефект инструмента спринта
**Статус:** исправлено в этапе 0, покрыто спекой
**Источник:** ревью Codex, подтверждено воспроизведением

`const ratio = value++ / divisor; // комментарий` — слеш деления принимался за
начало литерала регекспа, первый слеш `//` за его закрытие, комментарий терялся
целиком. Добавлены два правила: закрывающая кавычка и постфиксные `++`/`--` дают
значение, значит слеш делит. В репозитории такого кода сегодня нет — диффтест
против парсера TypeScript по 753 файлам даёт ноль пропусков и до правки, — но
дефект был бы внесён первой же строкой нового кода.

### 0.15 Блок бюджета говорил про заявленный объём, умалчивая про случай без заголовка

### 0.16 «Каждая из опций умеет переписать `baseURL`» — неверно для `retry`

**Файл:** `src/runtime/modules/common/utils/apiRequestPolicy.ts`
(блок над `CLIENT_OWNED_REQUEST_OPTIONS`)
**Категория:** разъехавшийся комментарий
**Статус:** текст исправлен в этапе 0
**Источник:** ревью Codex, подтверждено по типам ofetch

Обоснование запрета утверждало, что переписать `baseURL` или сам `request` умеет
**каждая** опция из списка. Для двух из семи это неверно: `retry?: number | false`
и `retryStatusCodes?: number[]` — числа, переписать они не могут ничего. Роли
разные: контекст получают хуки и функциональный
`retryDelay?: (context) => number`, и повтор уходит с `{ ...context.options }`
(`shared/ofetch.*.mjs:181-187`), а `retry` и `retryStatusCodes` лишь **разрешают**
повтор, который переиспользует уже авторизованные заголовки. Неточность была и в
русском оригинале; в переводе роли разделены — иначе security-рационал читается
слабее, чем есть.

### 0.17 «На заголовках» читалось как «в заголовках»

**Файл:** `src/runtime/modules/common/utils/apiRequestPolicy.ts`
(блок над `normalizeRequestAbortError`)
**Категория:** неточность перевода
**Статус:** исправлено в этапе 0
**Источник:** ревью Codex

`reports the signal's reason both on the headers and while reading the body` —
буквальный перенос «и на заголовках, и на чтении тела». По-английски читается,
будто `reason` лежит в заголовках, тогда как речь о **фазе** ожидания заголовков.
Переписано через фазы. Там же сняты кальки `honest text of an unknown outcome` →
`truthful unknown-outcome message` и `get its reconciliation` → `trigger
reconciliation`.

### 0.18 Тезис про лимит чтения был перевёрнут

**Файл:** `src/runtime/modules/persistence/server/utils/requestBodyLimits.ts`
(блок над `withMultipartFormData`)
**Категория:** неточность перевода
**Статус:** исправлено в этапе 0
**Источник:** ревью Codex

`The file type is not subject to the body bounds` — буквальный перенос «тип файла
границам тела не подчиняется», и по-английски он читается наоборот: будто
ограничения тела на тип файла не распространяются. Настоящий тезис — лимит чтения
**нельзя выбрать по типу**, потому что тип становится известен только после
полного чтения тела. Переписано прямо. Русский оригинал допускал то же прочтение,
но следующая фраза его снимала.

### 0.19 Системный слой калек в первом заходе перевода

**Файлы:** оба эталонных
**Категория:** качество перевода
**Статус:** исправлено в этапе 0
**Источник:** ревью Codex

Шесть буквальных переносов, которые нельзя тиражировать на 22 тысячи строк:
`flies out as it is` → `propagates unchanged`; `as ofetch leaves a GET` →
`as with an ofetch GET`; `the per-method timeout ceiling and detecting` →
`selecting the timeout ceiling for each method and detecting` (в первом варианте
существительное и герундий стояли в одном перечислении); `the client's own limit
is not spent` → `the client has not exhausted a request quota`; `returned
outwards` → `returned to the caller`; `lie under chunked transfer` → `misreport
the size under chunked transfer` (замену на `be absent or misreport the size`
не взял — она теряет механизм chunked transfer, а он здесь и есть причина).

**Вывод для остальных этапов:** перевод длинного блока требует отдельного
редакторского прохода на естественный технический английский. Дословный перенос
сохраняет структуру и нюанс, но оставляет кальки, а в двух случаях из этого захода
буквальность **перевернула** технический тезис.
