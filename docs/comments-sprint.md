# Спринт: комментарии на английский, чистка template/style

## Контекст

Комментарии в кодовой базе написаны по-русски: **21 599 строк** в `.ts`/`.vue`/`.scss`/`.sql`/`.mjs`
плюс **437 строк** русских HTML-комментариев. Проект готовится к публикации как npm-пакет, и
комментарии — тот слой, который уедет к внешнему разработчику нечитаемым. Самый наглядный
случай уже в проде: `src/module-scss.ts:58` пишет **русскую шапку комментария в SCSS-файл
внутри проекта потребителя**.

Комментарии при этом высокого качества: они объясняют **почему** принято решение и называют
дефект, который к нему привёл (`common/utils/apiRequestPolicy.ts` — почему повторы запрещены;
`builder/publish/utils/currentPageWrite.ts` — почему освежение списка не входит в результат
операции). Это не шум и не текст, который переводится регекспом: перевод обязан сохранить
нюанс, а по ходу чтения файла — проверить, что комментарий всё ещё верен. Точечная проверка
уже нашла пять разъехавшихся с кодом (раздел «Известные находки»).

Решения владельца, принятые при планировании:

- **Границы**: комментарии + имена кейсов в тестах (~2 000 русских `describe`/`it`) +
  dev-сообщения (`throw`/`console`) + локальные `README.md` в `composables/`/`utils/` (34 файла).
- **Ревью по KISS/DRY, оптимизации и доменам — только список находок, без правок.** Находки
  пишутся в `docs/comments-sprint-findings.md`, правки логики — отдельный спринт после.
  Причина: перевод не должен прятаться внутри рефакторинга, иначе находку ревью не отличить
  от опечатки перевода, а `git bisect` бесполезен.
- **template/style**: секции **внутри SFC** чистятся полностью, но ~110 строк рационала
  (записанные дефекты, замеры контраста, node-id макета) **сначала переезжают в `<script>`**,
  потом удаляются.
- **Самостоятельные `.scss` пакета — исключение** (решение принято в этапе 10, взамен
  прежнего «чистить и переносить SassDoc в `README.md`»): у отдельной таблицы стилей нет
  соседнего `<script>`, поэтому её рационал и SassDoc `public/**` остаются на месте,
  переведённые. Гейт пропускает префикс `src/runtime/assets/scss/`.
- **Приёмка** — скрипт `scripts/comment-language-check.mjs`. В `lint:check` не встраивать;
  штатные проверки и `sl:fix` владелец прогоняет сам.

### Ловушки инструментов

1. **`<!--[\s\S]*?-->` внутри регекспа.** `persistence/server/utils/fileSignatures.ts:29` — это
   **не комментарий**, а литерал регекспа для проверки SVG. Репо-широкий strip `<!--…-->` ломает
   валидацию загрузки SVG. Удаление HTML-комментариев вести только по секции `<template>`.
2. **Русские комментарии внутри template-литералов — закрыто.** Лексер их пропускает
   (это содержимое строки), регексп попадает и может испортить литерал, поэтому все три
   файла правились вручную: `common/utils/bricks/containerCss.ts` в этапе 1 (там же
   выяснилось, что перевод таких комментариев режим `--diff` считал правкой кода —
   починка гейта описана в находке 1.7), `layouts-blocks/utils/deviceVisibilityCss.ts` —
   в этапе 3, `persistence/server/postgres/postgresAuthAdapter.ts` (4 строки SQL `--`) —
   в этапе 6. Правило остаётся в силе для нового кода.
3. **`^\s*(//|/\*|\*)` теряет ~470 строк** — продолжения многострочных `<!-- -->` и `/* */` не
   несут префикса. Счётчик и гейт делать состояние-машиной, не регекспом по началу строки.
4. **`migrations/0001_init.sql` под checksum-контролем.** `src/cli/bricks-migrate.mjs:243-245`
   валит правку («Released migrations must not be edited»), `scripts/integration-smoke.mjs:189`
   ассертит отсутствие дрейфа. Порядок из `AGENTS.md` обязателен: правка → пересчёт строки в
   `bricks_schema_migrations` (`src/cli/bricks-migrate-checksum.mjs`) → 0 pending. DDL не меняется.
5. **Prettier комментарии не переносит** (`printWidth: 100`, `tabWidth: 4`) и не жалуется.
   Перенос строк — руками. `oxlint max-lines: 500` — удаление и перевод только укорачивают.

## Целевой стиль

Англоязычного прецедента в репозитории **нет**: три «английских» файла содержат только
`// #region` и тривиальный JSDoc. Эталон регистра — `common/utils/apiRequestPolicy.ts`
(шапка) и `persistence/server/utils/requestBodyLimits.ts` (шапка плюс блок над
`INFLIGHT_MULTIPART_BUDGET_BYTES`); что именно им зафиксировано — в
`comments-sprint-log.md`.

- Одна строка JSDoc: глагол в 3-м лице, без точки — `/** Toggles checkbox on Enter key (parity with native behavior) */`
  (`ui/base/checkbox/BricksCheckbox.vue:56`).
- Длинные блоки: сохранять структуру «решение → отброшенная альтернатива → дефект, который
  к этому привёл». Нормативные формулировки оставлять нормативными:
  `common/utils/bricks/routePaths.ts` запрещает хардкод `/bricks` — в переводе это должно
  остаться запретом, а не описанием.
- Орфография: **американская** (`behavior`, не `behaviour`). Три британских написания в уже
  готовых английских комментариях переписаны в этапе 2 (`behaviour` в `BricksCheckbox.vue`,
  `Sanitises`/`Sanitised` в `inputs/utils/bricksInput.ts`); в переводе следить за
  `cancelled`, `towards`, `labelled`, `neighbouring` — они лезут сами.
- **Кавычки только прямые `"…"`.** Французские `«…»` в проекте не встречаются ни разу за
  восемь закрытых этапов; house-style для scare-quotes — `"…"`
  (`common/utils/apiRequestPolicy.ts:235,327`). Из русского текста они переносятся сами:
  в этапе 9 их накопилось 46 в девяти файлах, поймало ревью, а не гейт.
- **Претензию к регистру проверять грепом по закрытым областям, а не на вкус.** В этапе 9
  ревью назвало калькой три оборота, которые оказались сложившимся регистром проекта
  (`answer 404` — шесть вхождений в `server/`, `travels into` — шесть в `common/`,
  `there is nobody left` — `common/types/brickManifest.d.ts:32`). Приняв их, перевод
  уехал бы от собственного эталона.
- `// #region` уже английские везде (~1 630 маркеров), кроме **9 в `src/module.ts`**
  (:99, :130, :146, :152, :165, :182, :203, :344, :351). У `:344` метка вдобавок обрезана —
  открытая скобка не закрыта.
- **Расхождение живёт в копии, а не в оригинале.** Проверять не только «верен ли
  комментарий здесь», но и «не повторяет ли он то, что уже описано у владельца механики»:
  в этапе 8 восемь комментариев в семи файлах повторяли рационал lazy-гейта и в повторе
  теряли оговорку про настраиваемый префикс, тогда как сам гейт описывал его верно.
  Этап 9 добавил к этому масштаб: оригинал бывает **выше в том же файле** — шапка
  матрицы прав перечисляла содержимое манифеста верно, а её же локальный комментарий
  двадцатью строками ниже — сокращённо (находка 9.6).
- **Дословный перенос сохраняет и чужую ошибку факта.** Редакторский проход её не ловит,
  потому что ищет кальки: в этапе 9 через оба прохода прошло утверждение «в prod-сборке
  нет Vite-конвейера» (`nuxi build` и есть Vite), поймало ревью. Утверждение о чужом
  слое проверять по этому слою, а не по гладкости фразы.
- **Редакторский проход — отдельным заходом после перевода, а не «по ходу».** Три этапа
  подряд дословный перенос проходил гейт и падал на редактуре: точки в JSDoc, ширина,
  кальки. Гейт этого не ловит вовсе.
- **Убирать по ходу перевода** (это работа с комментарием, а не правка кода):
  10 приписок `(находка ревью)` — процессная метаинформация, читателю не говорит ничего
  (`builder/app/composables/usePageThumbnail.ts:112,130,180`, `useBuilderSession.ts:401`,
  `useBuilderSessionAddressSync.ts:68`, `publish/utils/currentPageWrite.ts:141,207`,
  `publish/stores/publish.ts:179,273`, `app/composables/useComponentLibrary.ts:53`);
  висячую ссылку `(см. modules-restructure.md)` на несуществующий файл
  (`builder/shell/sidebar/types/composables.d.ts:23`) — `AGENTS.md` прямо требует такие убирать;
  закомментированный мёртвый код `shell/toolbar/components/TheBuilderShellToolbar.vue:47-69`
  (там же живой JSDoc над мёртвой функцией — читается как рабочий код).

## Правила для template и style

Секции `<template>` и `<style>` **внутри SFC** остаются без комментариев. Остаток к
удалению даёт колонка `tpl/style` гейта: **966 строк** после закрытия этапа 11, все — в
`.vue` этапов 12–19.

**Самостоятельные таблицы стилей пакета под это правило не подпадают** — всё, что лежит по
префиксу `src/runtime/assets/scss/`. Решение владельца в этапе 10: правило писалось для
`<style>` внутри SFC, где рационал переселяется в соседний `<script>`; у отдельно стоящего
`.scss` соседа нет, а рационала там ~150 строк, которого больше нигде нет (две зоны
reset'а, лестница z-index, разбор переходов). Он остался на месте и переведён; гейт
пропускает префикс предикатом `isMarkupCommentAllowed`. Перевод при этом не отменён:
кириллица в этих файлах гейт валит.

Осторожно с записью глоба в этом файле: `**` внутри инлайн-кода схлопывается с жирным
выделением, и prettier переписывает абзац, склеивая слова с кодом. Писать префикс без
глоба.

**Шаг 1 — перенести, потом удалять.** ~110 строк несут знание, которого больше нигде нет.
Переезжают в `<script setup>` (JSDoc на соответствующий `computed`/prop или блок в шапке
файла), сразу по-английски. Оба обязательных к переносу пункта плана закрыты в этапе 5
(оба свелись в одну шапку `RendererCloseButton.vue` — см. журнал).

Опыт этапа 2 по переносу (действует дальше):

- **Переносить не обязательно в `<script>`.** Если тот же факт уже описан в соседнем
  `types.d.ts`, знание доносится туда, а не копируется в компонент: запрет на дубль
  рационала соседнего файла сильнее буквы «переезжает в `<script setup>`».
- **Шапка компонента — не свалка.** После переноса всего рационала `BricksImage`
  получил шестидесятистрочную шапку, повторяющую то, что объяснено у самого кода;
  ревью справедливо назвало это нарушением DRY. Факт кладётся к ближайшему
  `computed`/`ref`, в шапку — только то, что не привязано к одному месту.
- **Удаление комментария из блока объявлений оставляет пустую строку**, которую
  стандартный `declaration-empty-line-before` считает нарушением: прежде её прикрывал
  `ignore: ["after-comment"]`. Убирать сразу — тогда `sl:fix` не нужен вовсе (в этапе 2
  предсказанного покраснения stylelint не случилось).
- **Ничего не переставлять в CSS ради линтера.** Перестановка свойств — правка кода, и
  `--diff` её показывает; в этапе 2 правило оказалось зелёным и без неё.

**Шаг 2 — удалить всё остальное**, кроме жёсткого allow-list:

| Оставить дословно                                      | Причина                                                                                                                                                               |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `layouts-blocks/components/BlockSvg.vue:110,117`       | `eslint-disable`/`enable vue/no-v-html`                                                                                                                               |
| `layouts-blocks/components/BlockAccordion.vue:116,140` | `eslint-disable-next-line vue/no-v-html`                                                                                                                              |
| `ui/base/checkbox/BricksCheckbox.vue:151,154`          | `stylelint-disable`/`enable` — иначе `-webkit-mask-image` валит `order/properties-order`; проверено в этапе 2 (`property-no-vendor-prefix` в `.stylelintrc` выключен) |
| `assets/scss/common/_normalize.scss:16,191`            | `stylelint-disable`/`enable` — прикрывает **175 строк вендоренного normalize.css**; удаление зальёт сборку ошибками                                                   |
| `assets/scss/common/_normalize.scss:1-13`              | атрибуция MIT для вендоренного кода                                                                                                                                   |

**Шаг 3 — отменён вместе с этапом 10** и оставлен здесь как запись решения. Предполагалось
перенести 94 строки SassDoc из `public/` в README и три ловушки-предупреждения туда же.
Взамен: SassDoc остался в своих файлах (он документирует публичный SCSS-API пакета, и в
README у него был бы читатель-потребитель, а не автор брика), а ловушки уехали к владельцам
в коде — `src/module.ts`, `useBricksConfig.ts` и кейс `styleIsolation.spec.ts`, — оставив на
местах правки однострочные ссылки. Подробности и почему именно так — в журнале и находках
10.1–10.4, 10.11.

**После удаления stylelint закономерно краснеет**: `rule-empty-line-before` и
`at-rule-empty-line-before` настроены с `ignore: ["after-comment"]`, и правило, стоявшее
прямо под комментарием, теперь требует пустой строки. Правится `npm run sl:fix` — прогоняет
владелец. Без этого хук `.lintstagedrc.cjs` заблокирует коммит: stylelint там без `--fix`.
Тесты, читающие CSS, комментарии сами вырезают (`styleIsolation.spec.ts:73`,
`rendererCloseButtonParity.spec.ts:79`) — удаление им безразлично. В этапе 10 покраснения не
случилось: комментарии там не удалялись.

### dev-сообщения (сквозь этапы)

Русских `throw`/`console` в `src/runtime` почти нет — правится в этапе своего домена:
`common/composables/useBricksDevices.ts:62` (закрыт в этапе 1),
`render/composables/useRendererDataSources.ts` (три штуки, закрыты в этапе 5),
`server/middleware/auth.ts:109,242` и `server/utils/bricksComponents.ts:24`
(закрыты в этапе 7).
Build-time закрыто в этапе 9: `brick-literals.ts` 13, `brick-metadata.ts` 13,
`module-backend-config.ts` 14, `module-runtime-config.ts:78`, `module.ts:230,257,328`.
Заодно выяснилось, что диагностику из `module-backend-config.ts` гейт не видит вовсе —
она приходит через `resolution.errors.push`, а колонка `ru msgs` считает только аргументы
`throw`/`console` (находка 9.5). Для этапа 23 (`scripts/**`, 46 сообщений) это значит, что
нуля по колонке недостаточно: сообщения там надо перечитывать глазами.
В `src/runtime` **нет** русских `statusMessage` (все 124 `createError` английские) и нет
русских тостов.

**Исключение:** `server/utils/bricksComponents.ts:67` — русский текст в
`createError({ data: { description } })` **пересекает HTTP-границу** и может отрендериться в
интерфейсе. Не переводить, записать в находки как i18n-долг. Закрыто в этапе 7:
гейт знает об этом решении через `MESSAGE_KEPT_RUSSIAN` (ключ — точный литерал), долг
записан находкой 7.6.

## Приёмка

`npm run comments:check` (устройство и решения — `comments-sprint-log.md`):

```
npm run comments:check                                    # отчёт по всем областям
npm run comments:check -- --area=<id>                     # закрытие этапа: падает при любом остатке
npm run comments:check -- --area=<id> --metric=comments   # закрытие по одному счётчику (этапы 21 и 22)
npm run comments:check -- --list                          # каждая строка-нарушитель
npm run comments:check -- --diff                          # рабочее дерево против HEAD: только комментарии
```

Порядок закрытия этапа: `--area=<id>` даёт ноль → `done: true` у этой области в
`scripts/comment-sprint-areas.mjs`. После этого вернувшийся русский комментарий валит
обычный прогон без флагов. В `lint:check` гейт **не** встраивается — по решению владельца.

**Верификация «код не менялся»** обязательна для всех этапов, кроме 22 и 24:
`npm run comments:check -- --diff`. Это сильнее линтеров — доказывает отсутствие правки
логики, а не её безвредность. Колонка `literals` информационная: кириллица внутри
шаблонных литералов (ловушка №2) гейт не валит, её правят руками — кроме четырёх
файлов генерируемого вывода в колонке `gated`. Колонка `ru msgs` покрывает
dev-сообщения (`throw`/`console`) из раздела ниже.

Штатные проверки (`type-check`, `oxlint`, `sl:fix`, `stylelint`, `vitest`, `deps:check`) и
`npm run format` прогоняет владелец. Единственное место, где линтер закономерно краснеет
сам по себе, — этапы 2, 3 и 10 (удаление CSS-комментариев, см. выше).
