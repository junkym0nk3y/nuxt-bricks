# Долг кода: находки сплошного ревью

**Срез:** 23 августа 2026 года.

Здесь лежат находки, оставшиеся после сплошного прохода по всем комментариям
репозитория. Сам проход закончен: комментарии переведены, разъехавшиеся с кодом
формулировки исправлены текстом сразу. В этих файлах — то, что текстом не
закрывается: правки логики, мёртвый код, дубли, нарушения правил проекта.

Каждый пункт самодостаточен: что не так, чем подтверждено, что произойдёт с
пользователем или интегратором, куда чинить. Читать без внешних документов.
Ссылок на файлы-планы и на идентификаторы задач в пунктах нет намеренно —
расшифровать их негде (правило `AGENTS.md`).

## Как этим пользоваться

- Номера пунктов внутри файла — только для чтения вслух. **Идентификаторами они
  не являются**: ссылаться на них из кода, тестов и коммитов нельзя, при
  следующей ревизии они сдвинутся. Между пунктами ссылки идут по названию.
- **Закрыл пункт — удали его из файла** и перенумеруй остальные. Список
  сокращается, а не помечается галочками: отметка «сделано» превращает файл в
  журнал, а журнал никто не перечитывает. История правки и так лежит в git.
  То же правило повторено в шапке каждого файла — потому что входят в них
  напрямую, минуя этот индекс.
- Закрывая пункт, проверь, не ссылались ли на него по названию из других
  файлов: если ссылались, снять или перенаправить ссылку тем же заходом.
- Часть пунктов помечена «вживую не воспроизведено» или «требует проверки» — там
  записан разбор по коду, а не наблюдение. Перед починкой воспроизводить.
- Это единственная очередь работ проекта: релизного бэклога отдельным документом
  больше нет, его пункты распределены здесь.
- Порядок закрытия — раздел «Роадмап» ниже: код по цене ошибки, начиная с П2.
  Решения, определявшие часть очереди, уже приняты и лежат в самих пунктах.

## Приоритет — не срочность

Шкала расставлена по цене ошибки. П2 — дефект с ограниченным радиусом: неверный
результат в одном сценарии, недостижимая опция, залипший край. П5 — там, где код
работает верно, но расходится с собственными правилами проекта и потому дороже в
поддержке. Верхняя ступень — потеря данных и молчаливый отказ — на этом срезе
пуста: пунктов такого класса в очереди больше нет.

Срочность живёт в треках: пункт из `release-readiness.md` может быть нужнее любого
дефекта, а фича с готовым макетом — нужнее чистки мёртвого кода. Шкала
упорядочивает **долг между собой**, а не долг против всего остального. Как это
сведено в один порядок работ — в роадмапе ниже.

Порядок внутри файла — от большего радиуса к меньшему, но это подсказка, а не
предписание: пункты независимы, кроме прямо названных связок («чинить вместе
с …», «решать заодно с …»).

## Роадмап: в каком порядке закрывать

Этапы задают **порядок**, а не даты. Внутри этапа порядок свободный; переход к
следующему — по критерию выхода, а не по проценту сделанного. Пункты названы
заголовками: номера в файлах сдвинутся при первой же закрытой находке.

Решения, без которых часть очереди переделывалась бы, приняты и разложены по
пунктам: каждый ответ лежит в самой находке, которую он определяет. Со стороны
репозитория публикация закрыта — `LICENSE`, ссылки, changelog, канал security и
release workflow с provenance на месте, `npm run smoke:pack` зелёный. Осталось то,
что делается не кодом: репозиторий публичным, первая ручная выкладка, trusted
publisher (см. «Публикация ждёт публичного репозитория» в
[готовности](release-readiness.md)).

### Этап 1. Гейт начинает ловить регрессии — закрыт

Этап закрыт: пункт «Хвосты релизного гейта» удалён из
[готовности](release-readiness.md). Что вышло по ходу, если понадобится
восстановить причины решений:

- **e2e.** Появилась вторая фикстура (`e2e/fixture-auth`) — `auth.mode: 'database'`
  несовместим с `backend.mode: 'external'`, поэтому вход проверяется на builtin-
  режиме с поддельным `IAuthAdapter` и storage поверх того же fake backend. Четыре
  сценария: вход/выход и неверный пароль, импорт JSON, публикация из UI, конфликт
  версий с восстановлением. Fake backend научен преконди́ции `expectedRevision` и
  категориям медиатеки, а счётчик ревизий у него начинается с единицы, как в схеме
  БД: ноль — состояние, которого не бывает, и сервер отвергал такую преконди́цию.
- **Покрытие.** Пороги стоят по каталогам (девятнадцать глобов); что каждый
  исполняемый файл попадает ровно под один порог, сторожит спека.
- **axe.** Проверка идёт внутри существующей джобы e2e на четырёх состояниях: экран
  входа, дашборд с открытой панелью, редактор с развёрнутым редактором галереи,
  медиатека с плитками. Узлы оверлея ошибок Nuxt и devtools исключены — это чужой
  код; поддеревья приложения не исключаются.
- **Найдено и починено гейтом:** тост во время серверного рендера ронял страницу
  целиком (`requestAnimationFrame` на сервере), `<html>` был без `lang`, редактор и
  экран входа — без `<title>`, скрытый инпут загрузки — без подписи,
  `aria-expanded` садился на обёртку тултипа, а мелкий текст в семи местах не
  проходил AA по контрасту.

### Этап 2. Безопасность и вес — закрыт

Этап закрыт: оба пункта удалены из [готовности](release-readiness.md). Что вышло по
ходу, если понадобится восстановить причины решений:

- **Параметры scrypt.** Взят не `N=2^17, r=8, p=1` из записанного разбора, а
  OWASP-эквивалент `N=2^14, r=8, p=5`: `p` множит время, а не таблицу памяти, поэтому
  стойкость та же, а деривация просит 16 МиБ вместо 128 и пролезает в дефолтный
  `maxmem` node. Замеры (`scripts/benchmark-scrypt.mjs`): 92 мс против 18 мс прежних,
  пик RSS при двух одновременных +33 МиБ против +513 МиБ у варианта с `N=2^17`.
  `maxmem` всё равно передаётся явно — параметры деривации выбирает строка из базы, и
  потолок единственное, что стоит между враждебной записью и аллокацией любого
  размера; строка выше потолка отвергается как нечитаемая.
- **Семафор.** `maxConcurrent` снижен с 4 до 2, очередь с 32 до 8 — не из-за памяти
  (её стало меньше), а из-за пула libuv: четыре деривации по ~0.1 с занимали бы все
  четыре потока, и обработка картинок ждала бы за логинами.
- **Rehash-on-login.** Контракт адаптера получил `rehashUserPassword` — отдельный
  метод, потому что запись обязана НЕ поднимать поколение и НЕ рвать сессии: иначе
  вход выбрасывает сам себя тем cookie, который только что выдал. Условие записи —
  прежний хеш плюс поколение плюс активность. Деривация идёт оппортунистической формой
  шлюза: при занятых слотах рехеш пропускается, а не встаёт в очередь впереди тех, кто
  ждёт входа. Решение обновлять — проверка доминирования, а не «параметры отличаются»:
  последнее понизило бы хеш, посчитанный более дорогими параметрами.
- **Найденная связь, которой в разборе не было.** Признак «пароль всё ещё дефолтный»
  считается сравнением строк прямо в запросе сессии, поэтому сидовый хеш обязан быть
  написан нынешними параметрами: отстань он от них — первый вход дефолтного
  администратора перехешировал бы строку, сравнение перестало бы совпадать, и
  предупреждение погасло бы при живом дефолтном пароле. Записано в контракте рядом с
  флагом.
- **Вес редактора.** `vanilla-jsoneditor` и `json-editor-vue` сняты; подсветка
  собрана своим лексером без зависимостей (prismjs не понадобился: его 3.7 КБ шли бы
  с HTML-строкой в `v-html`, а токены-текстовые-узлы такой границы доверия не создают).
  Поверхность редактора: **656 → 349 КБ gzip**, ушёл вендорный чанк на 309 КБ вместе
  с `ajv`, `jmespath`, `json-source-map` и `natural-compare-lite` из production-дерева.
  Бюджет в `scripts/bundle-budget.mjs` считает редактор ПРИРОСТОМ над published, а не
  суммой: иначе рост entry съедал бы его запас. Скрипт отказывается, когда выборка
  поверхности пуста — иначе переименование домена сделало бы бюджет вечно зелёным.
- **Подсветка одноцветная, и это замер, а не вкус.** Синие ключи дали 4.08:1 на фоне
  сайдбара в тёмной теме (нужно 4.5), а одним цветом обе темы не закрыть: светлая
  требует яркости ниже 0.18, тёмная выше 0.27. Цветной акцент потребует пары
  AA-безопасных переменных в общей палитре — это решение о палитре, не о редакторе.
- **Мимо счёта:** редактор JSON в интерфейсе достижим только через свойство типа
  `object`, а его не объявляет ни один блок пакета — поэтому в e2e-фикстуре появилось
  такое свойство, и axe-проверка состояния редактора теперь его действительно видит.

### Этап 3. П2 — остаток

Двадцать пять пунктов из двадцати семи закрыты. Что вышло по ходу, если понадобится
восстановить причины решений:

- **Мост правила переноса.** Правило допустимости (`evaluateComponentMove`) осталось в
  билдере, а зонам drop оно доезжает нейтральным контрактом в `common`
  (`COMPONENT_DROP_GUARD_KEY`): провайдер поднимает канвас, по одному на вьюпорт —
  Figma-режим рисует все листы сразу, и вместимость сетки считается в клетках своего
  листа, а не активного вьюпорта стора. Слоты brick-компонентов подключены к тому же
  мосту: у них была своя реализация drag'n'drop. Локальная проверка drop на самого себя
  снята — мост покрывает и её. Отказ стора больше не глотается: причина уходит в тот же
  `useComponentMoveFeedback`, что и у дерева, а drag-сессия закрывается через `finally`
  на всех путях, включая отказ — раньше ранний выход рассчитывал на поздний нативный
  `dragend`.
- **Роль вторичного текста.** `--bricks-text-muted` (`#636a77` в светлой теме,
  `#9aa2b1` в тёмной, плюс сброс на светлый внутри `.bricks-canvas`) заменила бледные
  ступени палитры в 29 объявлениях реального текста. Остальные вхождения `base-300/400`
  оказались иконками, рамками, фонами и погашенными состояниями — контраст текста там не
  при чём, и их правка сломала бы иерархию. Значения выбраны замером: муть светлой темы
  проходит AA (4.5) на белом, на `base-50` и на карточках `base-100`, тёмной — включая
  поднятую поверхность, где дефолтный `base-500` давал 3.85.
- **Гейт вырос на пятое состояние** (модалка создания страницы) и сразу нашёл два
  нарушения: подпись карточки-источника на выбранной карточке давала 4.44 (роль
  вторичного текста подняла до 5.0), а скрытый инпут выбора JSON-файла был без подписи —
  как и два его брата в панели схемы и в модалке профиля.
- **Бюджет прогона источников данных** теперь накрывает и загрузку brick-модулей:
  таймер заводится до сбора запросов, сам сбор идёт `Promise.all` по уникальным путям и
  ограничен ожиданием (динамический import отменить нечем), а второй фазе достаётся
  остаток бюджета, а не полный заново.
- **Отрицательный кеш снят везде**: ни `loadBrickDataSources`, ни `loadBrickComponent`
  больше не запоминают неудачу — кеш компонентов живёт на уровне модуля и на сервере
  переживал запросы, то есть одна сборка без экспорта отвечала «нет компонента» до конца
  жизни процесса. Одного этого мало: async-обёртка Vue держит отклонённый запрос внутри
  себя и лоадер второй раз не зовёт, поэтому упавшая обёртка вылетает из кеша вместе с
  отказом — иначе она отравляла путь ровно так же (нашло ревью).
- **Новый блок из библиотеки судится тем же правилом**, что и перенос
  (`evaluateComponentInsertion`): источника в схеме у него нет, но занятый одиночный слот,
  полная сетка и потолок глубины отказывают ему точно так же — и мост спрашивает это до
  подсветки. Заодно закрыт откат: создание и присоединение стали одним шагом для истории,
  а при отказе стора компонент удаляется и причина уходит тостом — прежде он оставался на
  корне канваса (нашло ревью).
- **Потоковая загрузка сделана.** Форма читается потоковым парсером
  (`@fastify/busboy` прямой зависимостью): текстовое поле становится значением, файловая
  часть — потоком. Видео уходит в бакет по частям через новый обязательный метод
  контракта (`uploadFileStream`), в памяти живёт один кусок; картинка по-прежнему
  собирается буфером, потому что sharp работает по байтам. Заодно у картинок исчезла
  вторая копия тела: прежний читатель буферизовал форму целиком, а разбор копировал её
  снова. Что вышло по ходу:
    - **Потолков стало два, и оба нужны.** Один считает всё тело (границы, заголовки
      частей, мусор за закрывающей границей), второй — одну часть. С одним первым форма
      из тысячи крошечных полей пролезала бы под потолком части, с одним вторым
      конверт остался бы без границы вовсе.
    - **Обрезанная часть — отказ, а не короткий файл.** Парсер на своём `fileSize` не
      падает: он заканчивает поток и ставит `truncated`. Без проверки этого флага
      усечённое видео выглядело бы успешно доехавшим и легло бы в бакет.
    - **Оборванное тело — отказ, а не пустая форма.** Признак — `req.complete`: без него
      обрыв на удачном месте выглядел бы как корректно закрытая форма.
    - **Бюджет сменил предмет** — не сумма заявленных байт, а число одновременно
      читаемых форм (четыре, как у семафора sharp: загрузка картинки занимает оба, и
      более широкий вход только строил бы очередь перед узким). Регистрация записи в БД
      вынесена ЗА слот: внешняя запись не должна занимать вход.
    - **Slowloris**: у входа мало слотов, поэтому появился потолок молчания клиента.
      Меряется ожидание нами следующего чанка, а не пауза между чанками — пауза, пока
      часть уходит в хранилище, это занятость сервера, и обрывать по ней живую загрузку
      нельзя.
    - **Уборка на отказе различает три состояния**: PUT отправлен (удалить объект),
      multipart создан и не завершался (abort), завершение отправлено и упало (abort и
      удаление — исход неизвестен, а ссылки на объект у вызывающего нет). Плюс окно,
      которое из приложения не закрыть: ответ на создание заливки мог потеряться, и её
      идентификатора не знает никто — отсюда требование lifecycle-правила в README.
    - **Часть отправляется, только когда за ней пришли ещё байты**: файл ровно в одну
      часть уходит одним PUT вместо трёх запросов multipart.
    - **Порядок полей формы стал значимым для видео**: категория впереди файла
      проверяется до заливки, позади — стоит заливки и удаления. Клиент переставлен,
      но чужой порядок остаётся рабочим — отказ по позднему полю удаляет уже
      залитый объект (для этого есть отдельная уборка «записи не будет»).
- **Осталась команда уборки осиротевших объектов** — отложена решением владельца: её
  нельзя считать проверенной без прогона на реальном бакете.

**Выход:** из двадцати семи пунктов этапа в очереди остался один — отложенная команда
уборки. Всё, что лежит в `p2-defects.md` помимо неё, найдено позже и к этому этапу
не относится.

### Этап 4. i18n одним проходом — закрыт

Этап закрыт: файл `i18n.md` удалён вместе с треком. Одной механикой «строка уезжает
в локали» он не закрылся — под ним оказались четыре разных класса текста, и решение
у каждого своё. Что вышло по ходу, если понадобится восстановить причины решений:

- **Сервер прозы в тело ответа не кладёт вовсе.** Русское `data.description` из 404
  «категория не найдена» снято, а не переведено: сервер не знает языка интерфейса,
  потребителя у поля не было, а ключ локали в HTTP-ответе связал бы серверный
  контракт с деревом переводов билдера. Подсказка ушла в английский `statusMessage`
  — туда же, где живёт вся остальная поверхность ошибок `/api/bricks/**`. Запись-
  исключение из `.claude/rules/comments.md` снята тем же заходом.
- **i18n остаётся зависимостью билдера.** `@nuxtjs/i18n` ставится только под
  `features.builder`, и ставить его безусловно нельзя: он навязал бы модуль
  потребителю, которому нужен один рендер, вместе со своими дефолтами роутинга, и
  не пролез бы в бюджет published (132 КБ gzip при нынешних 130). Поэтому текст
  published-поверхности разделён по видимости, а не переведён.
- **Посетителю не показывают состояние библиотеки.** Заглушка недоступного
  компонента осталась только у превью: тексты приезжают в `TheRenderer` пропом
  `placeholderLabels` от той поверхности, у которой есть переводчик. Published
  получает `null` и рисует пустой узел — с прежним grid-placement и `id`, иначе
  сосед упавшей клетки съезжает на её место. Тот же приём у подсказок пустых
  блоков: `emptyLabel` приходит с канваса через новое поле `t` в контексте
  биндинга, и `layouts-blocks` по-прежнему ничего не знает про vue-i18n.
- **Стартовый контент блока — не интерфейс.** Дефолт уезжает в схему при первом
  сохранении и с этого момента принадлежит человеку, а не билдеру, поэтому ключ
  локали в нём хранить нельзя. Структурный дефолт стал нейтральным (`''` у Text,
  `[]` у Accordion), а локализованный текст материализуется один раз — при сборке
  карточки библиотеки, через новое `seedProps` в определении блока. Смена языка
  меняет то, что появится у следующего блока, и не трогает уже созданные.
- **Мимо счёта нашлись ещё два места:** бейдж «Отключен» на канвасе и таблица фраз
  лоадера отдельным TypeScript-файлом. Фразы переехали в локали массивом (`tm` +
  `rt`), файл удалён; дефолтная подпись лоадера свелась к уже существовавшему
  `bricks.common.loading` — она совпадала с ним слово в слово.
- **Плейсхолдеры-примеры не переводятся.** `blog`, `spb`, `my-section`,
  `#section-id`, `item1, item2, item3` — образцы машинного значения, а не
  инструкции: перевод научил бы вводить неподходящее. Правило: переводим то, что
  обращено к человеку, оставляем то, что показывает синтаксис.
- **Хелпер перевода дорос до параметров.** `translateBricksKey` принимает значения
  интерполяции, и препятствие, записанное в пункте про приведение композера в
  `p4-duplication.md`, снято; два из семи мест переведены на хелпер заодно.

**Выход:** в исполняемом коде вне `locales/ru.json`, встроенной русской
документации и двух таблиц транслитерации кириллицы нет — это сторожит
`test/module/noCyrillicInCode.spec.ts`. Паритет ключей `ru`/`en` сторожит
`test/module/localeParity.spec.ts`: прежде его не было вовсе.

### Этап 5. Мёртвый код (П3) — закрыт

Этап закрыт: файл `p3-dead-code.md` удалён вместе с приоритетом, все тридцать три
пункта сняты. Что вышло по ходу, если понадобится восстановить причины решений:

- **Снятие мёртвого кода само находит мёртвый код.** Радиус трёх пунктов оказался
  шире записанного, причём находки вылезали цепочкой: проп тулбара держал `computed`
  в `useBuilderPage`, тот — поле в контракте возврата, а поле — ре-экспорт из
  `useBuilderPageWrite`; снятая ветка Figma-режима осиротила экшен стора
  (`setComponentDeviceVisibility`) вместе с его объявлением. Правило прохода: после
  каждого удаления грепать не имя пропа, а имя того, что его питало.
- **Общая фабрика payload вставки** (`builder/core/utils/componentInsertPayload.ts`)
  закрыла и пункт про `isInteractive`, и тройной дубль из П4 — они были одним
  дефектом с двух сторон. Место выбрано границами: `builder/canvas` не имеет права
  импортировать composition root, поэтому фабрика легла в `core`, а не в `app`.
  Заодно всплыло, что два из трёх путей вставки клали в схему `width: 0, height: 0`
  — полей, которых у компонента схемы нет: `addComponent` расстилал их спредом как
  есть, третий путь не клал никогда, и не читал их никто.
- **`isInteractive` снят целиком, а не «убран из схемы».** Цепочка «определение
  блока → карточка библиотеки → схема» писалась насквозь и не читалась нигде:
  интерактивный предпросмотр включается `interactivePreviewId` и доступен любому
  блоку, а поле объявлял один Accordion. Подключение поля к поведению сделало бы
  предпросмотр Accordion-only — это продуктовое решение, а не чистка.
- **Проп, который «no-op», нельзя просто снять с типа.** `bottom` у тултипа ничего
  не переключал (`side` возвращает `bottom` и без него), но передавали его девять
  мест, включая динамический проброс из `BricksIconButton`. Оставь их — Vue положил
  бы `bottom` на корневой узел уже как DOM-атрибут. Так же с `label` у
  `TextEditorArea`: он приезжает через `v-bind` из строки панели свойств, поэтому
  вместе с пропом пришлось научить строку не отдавать `label` редактору `textarea`.
- **Три решения владельца.** Хеш манифеста снят (задел под сверку хешей в dev, к
  которой так и не пришли — вместе с ним ушли поле контракта, заглушка сервера,
  копия в клиентском кеше и три спеки); страховка «поколение отправки» в формах
  шаблонов снята (дублирована в двух композаблах, запрос не отменяет, от unmount не
  защищает); проброс `csrftoken` → `X-CSRFToken` снят — читателя у него не было
  вовсе, все вызовы клиента идут в `/api/bricks/**`, где проверяется свой
  `x-bricks-csrf`, а в общих дефолтах заголовок ждал первого запроса на чужой origin,
  чтобы уехать туда вместе с ним.
- **Из двух experimental-флагов лишним был не тот, что казался.** `appManifest`
  модуль ставил в значение, которое у Nuxt и так по умолчанию; `inlineRouteRules`
  же реально менял конфигурацию потребителя — ради макроса `defineRouteRules`,
  который в `src/` не встречается ни разу.
- **Мимо счёта:** `.catch` восстановительного прогона источников данных снят вместе
  с обещанием предупреждения в лог (`useAsyncData` держит отказ внутри себя, до
  колбэка исполнение не доходит), а из шапки `BricksTagsEditor` ушла ссылка на
  переменную палитры, которую тот же заход и удалил.

**Выход:** `p3-dead-code.md` удалён, `knip:check`, `deps:check`, `lint:check`,
`type-check`, `npm test`, `test:coverage`, `dev:build` и `budget:bundle` зелёные.

### Этап 6. Дубли и правила (П4, П5)

Изначально этап был записан как фон: брать то, что трогает файл, уже открытый по
другой причине. Решением владельца он закрывается целиком и по порядку — иначе
семьдесят восемь пунктов не сходятся никогда, а часть из них связана друг с
другом так, что порядок важен (см. связки в самих находках).

**Выход:** оба файла пусты, `deps:check` и `type-check` зелёные без исключений.

#### Порядок партий

Партия — то, что делается одним заходом и уходит на одно ревью. Внутри партии
порядок свободный. **Номера партий идентификаторами не являются** — как и номера
пунктов, они сдвинутся; ссылаться на них из кода и коммитов нельзя.

Порядок не произвольный: сначала архитектурные и бандл-ограничители, потом
внутренности билдера, и в самом конце composition root и глобальные стили — их
зависимости к тому моменту уже перестают шевелиться.

Закрытые партии из списка удаляются, как и пункты.

1. **Атомарные действия components store.** `debouncedSaveToHistory` дважды ·
   приведение строки к числу · снятие `responsive` двумя способами ·
   `findSiblingContext`.
2. **Контракты property editors.** `clampToPropertyRange` · `inferPropertyType` ·
   `validatePropertyValue` · `handleNormalizeProps` · ре-экспорт
   `IInlineEditableProp`.
3. **Canvas height и переход viewport.** Замер высоты по контенту · потолок
   истории и длительность перехода · ожидание 450 мс.
4. **Превью карточки и типы SFC канваса.** Три watcher-а · высота превью из CSS ·
   интерфейсы пропсов внутри двух SFC канваса.
5. **Операции списковых property editors.** Редакторы аккордеона и галереи ·
   инлайновый SVG-шеврон.
6. **Контракты сайдбара.** Интерфейсы внутри девяти SFC · четыре композабла без
   типа возврата · `IPublishFormInitialValues`.
7. **TabBar как примитив кита и мелкие конвенции UI.** Категорийные табы
   медиатеки · корневой CSS-класс · `normalised` · `towards`.
8. **Резолвер, тема и стили сайдбара.** Нативный `<select>` · форс светлой темы ·
   два отступления в стилях сайдбара.
9. **Модель поверхностей медиатеки.** Модалка и раздел дашборда · мета-панель и
   панель деталей · `IImageLocation`.
10. **Point-lookup медиа у внешнего бэкенда.** `getMediaByUrl` · `cancelled`
    против `canceled`.
11. **Шаблоны целиком.** Формы сохранения и переименования · мета-строка ·
    интерфейс запроса в `utils/` · два композабла без типа возврата · порог поиска
    пикера.
12. **Переиспользование между доменами.** Задержка поиска втроена · приведение
    `$i18n as Composer`.
13. **Учётки и авторизация.** `formatUserDate` · список ролей ·
    `isPasswordActionVisible` · `openGeneration`.
14. **Конвенции типов домена публикации.** Инлайновые формы `defineProps` ·
    `IVersionRestoreStoreDeps` · `IUsePublishTemplateSurfaceOptions`.
15. **Превью и настройки билдера.** Исход `window.open` · `DARK_MODE_COOKIE` ·
    два `Date.now()` · `previewPagename`.
16. **Composition root и сессия.** `ensurePublishSettingsVisible` · пустые
    делегаты · два файла редактора у потолка `max-lines`. Партия поздняя и самая
    рискованная: превью, cookie и контракты сайдбара к этому моменту уже стоят.
17. **Документация: граница бандла и санитайзер.** Стили документации в
    глобальной таблице (закрывает сразу два заголовка П5) · статья мимо
    `sanitize`.

#### Сквозные ловушки этапа

- Общий хелпер класть **по направлению зависимостей**, а не по числу
  потребителей: `common` и `ui` не смотрят вверх, `render` — только в
  `common`/`layouts-blocks`, `persistence` остаётся server-only.
- Определения layout-блоков входят в published renderer. Импорт builder-утилиты
  оттуда не только валит `deps:check`, но и тянет код редактора в публичную
  поверхность.
- `budget:bundle` достоверен только после свежего успешного `dev:build` при
  **остановленном** dev-сервере, иначе меряется старый манифест. Вынос модуля из
  entry — половина экономии: чанк остаётся prefetch-абельным, пока не попал в
  исключение подсказки (`disableNonPublishedChunkPrefetch`).
- Проверять три поверхности отдельно: билдер, превью, published. Зелёный билдер
  не говорит ничего про render-only деплой.
- После правок публичных типов, `common` и build-time слоя обязателен
  `npm run build` — одного `type-check` мало.
- Новому сторожу — **мутационная проверка, и мутировать в том месте, где жил
  исходный дефект**, а не там, куда сторож смотрит. Иначе он зеленеет на той
  самой находке, ради которой написан.

### Попутно, не этапом

- **Разъехавшиеся тексты** ([stale-text](stale-text.md)) закрываются в том же
  коммите, что и правка рядом. Отдельного захода просят только те, что вводят в
  заблуждение: README про миграции, которых больше нет, и warning резолвера backend,
  обещающий отказ всего `/api/bricks/**`.
- **Не построенное** ([features](features.md)) — продуктовая дорожка, встаёт между
  этапами по решению владельца. Внутри порядок задан только у двух пунктов:
  предпросмотр сниппета выдачи идёт до предпросмотра карточки в соцсетях, они
  считают адрес одним composable.
