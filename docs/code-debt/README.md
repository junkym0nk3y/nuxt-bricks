# Долг кода: находки сплошного ревью

**Срез:** 23 августа 2026 года.

Здесь лежат находки, оставшиеся после сплошного прохода по всем комментариям
репозитория. Сам проход закончен: комментарии переведены, разъехавшиеся с кодом
формулировки исправлены текстом сразу. В этих файлах — то, что текстом не
закрывается: правки логики, мёртвый код, дубли, нарушения правил проекта.

Каждый пункт самодостаточен: что не так, чем подтверждено, что произойдёт с
пользователем или интегратором, куда чинить. Читать без внешних документов.
Ссылок на файлы-планы и на идентификаторы задач в пунктах нет намеренно —
расшифровать их негде (правило `AGENTS.md`).

## Как этим пользоваться

- Номера пунктов внутри файла — только для чтения вслух. **Идентификаторами они
  не являются**: ссылаться на них из кода, тестов и коммитов нельзя, при
  следующей ревизии они сдвинутся. Между пунктами ссылки идут по названию.
- Закрыл пункт — удали его из файла. Список сокращается, а не помечается
  галочками: история правки живёт в git.
- Часть пунктов помечена «вживую не воспроизведено» или «требует проверки» — там
  записан разбор по коду, а не наблюдение. Перед починкой воспроизводить.
- Это единственная очередь работ проекта: релизного бэклога отдельным документом
  больше нет, его пункты распределены здесь.

## Приоритет — не срочность

П1 — там, где цена ошибки максимальная: потерянная правка, неверные данные в
базе, захваченное пространство имён потребителя. П5 — там, где код работает
верно, но расходится с собственными правилами проекта и потому дороже в
поддержке.

Срочность живёт в треках: блокер публикации из `release-readiness.md` может быть
нужнее любого П1, а фича с готовым макетом — нужнее чистки мёртвого кода. Шкала
П1–П5 упорядочивает **долг между собой**, а не долг против всего остального.

Порядок внутри файла — от большего радиуса к меньшему, но это подсказка, а не
предписание: пункты независимы, кроме прямо названных связок («чинить вместе
с …», «решать заодно с …»).

## Связки между файлами

Пункты, которые дешевле делать вместе:

- сборщик сирот медиа ([П2](p2-defects.md)) и sweep аватаров
  ([архитектура](architecture-1.0.md)) — один проход с разными префиксами;
- доступность редактора галереи ([П2](p2-defects.md)) — предпосылка для
  axe-проверок в CI ([готовность](release-readiness.md));
- пороги покрытия ([готовность](release-readiness.md)) ставятся только после
  среза тестового набора ([решения владельца](owner-decisions.md));
- отказ от `vanilla-jsoneditor` ([готовность](release-readiness.md)) снимает
  половину веса поддерева редактора и одну уязвимость из `npm audit`;
- превью выдачи и превью соцкарточки ([не построенное](features.md)) считают
  адрес одним composable — порядок между ними задан.
