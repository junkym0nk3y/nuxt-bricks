# Долг кода: находки сплошного ревью

**Срез:** 23 августа 2026 года.

Здесь лежат находки, оставшиеся после сплошного прохода по всем комментариям
репозитория. Сам проход закончен: комментарии переведены, разъехавшиеся с кодом
формулировки исправлены текстом сразу. В этих файлах — то, что текстом не
закрывается: правки логики, мёртвый код, дубли, нарушения правил проекта.

Каждый пункт самодостаточен: что не так, чем подтверждено, что произойдёт с
пользователем или интегратором, куда чинить. Читать без внешних документов.
Ссылок на файлы-планы и на идентификаторы задач в пунктах нет намеренно —
расшифровать их негде (правило `AGENTS.md`).

## Как этим пользоваться

- Номера пунктов внутри файла — только для чтения вслух. **Идентификаторами они
  не являются**: ссылаться на них из кода, тестов и коммитов нельзя, при
  следующей ревизии они сдвинутся. Между пунктами ссылки идут по названию.
- **Закрыл пункт — удали его из файла** и перенумеруй остальные. Список
  сокращается, а не помечается галочками: отметка «сделано» превращает файл в
  журнал, а журнал никто не перечитывает. История правки и так лежит в git.
  То же правило повторено в шапке каждого файла — потому что входят в них
  напрямую, минуя этот индекс.
- Закрывая пункт, проверь, не ссылались ли на него по названию из других
  файлов: если ссылались, снять или перенаправить ссылку тем же заходом.
- Часть пунктов помечена «вживую не воспроизведено» или «требует проверки» — там
  записан разбор по коду, а не наблюдение. Перед починкой воспроизводить.
- Это единственная очередь работ проекта: релизного бэклога отдельным документом
  больше нет, его пункты распределены здесь.
- Порядок закрытия — раздел «Роадмап» ниже: код по цене ошибки, начиная с П2.
  Решения, определявшие часть очереди, уже приняты и лежат в самих пунктах.

## Приоритет — не срочность

Шкала расставлена по цене ошибки. П2 — дефект с ограниченным радиусом: неверный
результат в одном сценарии, недостижимая опция, залипший край. П5 — там, где код
работает верно, но расходится с собственными правилами проекта и потому дороже в
поддержке. Верхняя ступень — потеря данных и молчаливый отказ — на этом срезе
пуста: пунктов такого класса в очереди больше нет.

Срочность живёт в треках: пункт из `release-readiness.md` может быть нужнее любого
дефекта, а фича с готовым макетом — нужнее чистки мёртвого кода. Шкала
упорядочивает **долг между собой**, а не долг против всего остального. Как это
сведено в один порядок работ — в роадмапе ниже.

Порядок внутри файла — от большего радиуса к меньшему, но это подсказка, а не
предписание: пункты независимы, кроме прямо названных связок («чинить вместе
с …», «решать заодно с …»).

## Роадмап: в каком порядке закрывать

Этапы задают **порядок**, а не даты. Внутри этапа порядок свободный; переход к
следующему — по критерию выхода, а не по проценту сделанного. Пункты названы
заголовками: номера в файлах сдвинутся при первой же закрытой находке.

Решения, без которых часть очереди переделывалась бы, приняты и разложены по
пунктам: каждый ответ лежит в самой находке, которую он определяет. Со стороны
репозитория публикация закрыта — `LICENSE`, ссылки, changelog, канал security и
release workflow с provenance на месте, `npm run smoke:pack` зелёный. Осталось то,
что делается не кодом: репозиторий публичным, первая ручная выкладка, trusted
publisher (см. «Публикация ждёт публичного репозитория» в
[готовности](release-readiness.md)).

### Этап 1. Гейт начинает ловить регрессии — закрыт

Этап закрыт: пункт «Хвосты релизного гейта» удалён из
[готовности](release-readiness.md). Что вышло по ходу, если понадобится
восстановить причины решений:

- **e2e.** Появилась вторая фикстура (`e2e/fixture-auth`) — `auth.mode: 'database'`
  несовместим с `backend.mode: 'external'`, поэтому вход проверяется на builtin-
  режиме с поддельным `IAuthAdapter` и storage поверх того же fake backend. Четыре
  сценария: вход/выход и неверный пароль, импорт JSON, публикация из UI, конфликт
  версий с восстановлением. Fake backend научен преконди́ции `expectedRevision` и
  категориям медиатеки, а счётчик ревизий у него начинается с единицы, как в схеме
  БД: ноль — состояние, которого не бывает, и сервер отвергал такую преконди́цию.
- **Покрытие.** Пороги стоят по каталогам (девятнадцать глобов); что каждый
  исполняемый файл попадает ровно под один порог, сторожит спека.
- **axe.** Проверка идёт внутри существующей джобы e2e на четырёх состояниях: экран
  входа, дашборд с открытой панелью, редактор с развёрнутым редактором галереи,
  медиатека с плитками. Узлы оверлея ошибок Nuxt и devtools исключены — это чужой
  код; поддеревья приложения не исключаются.
- **Найдено и починено гейтом:** тост во время серверного рендера ронял страницу
  целиком (`requestAnimationFrame` на сервере), `<html>` был без `lang`, редактор и
  экран входа — без `<title>`, скрытый инпут загрузки — без подписи,
  `aria-expanded` садился на обёртку тултипа, а мелкий текст в семи местах не
  проходил AA по контрасту.

### Этап 2. Безопасность и вес — закрыт

Этап закрыт: оба пункта удалены из [готовности](release-readiness.md). Что вышло по
ходу, если понадобится восстановить причины решений:

- **Параметры scrypt.** Взят не `N=2^17, r=8, p=1` из записанного разбора, а
  OWASP-эквивалент `N=2^14, r=8, p=5`: `p` множит время, а не таблицу памяти, поэтому
  стойкость та же, а деривация просит 16 МиБ вместо 128 и пролезает в дефолтный
  `maxmem` node. Замеры (`scripts/benchmark-scrypt.mjs`): 92 мс против 18 мс прежних,
  пик RSS при двух одновременных +33 МиБ против +513 МиБ у варианта с `N=2^17`.
  `maxmem` всё равно передаётся явно — параметры деривации выбирает строка из базы, и
  потолок единственное, что стоит между враждебной записью и аллокацией любого
  размера; строка выше потолка отвергается как нечитаемая.
- **Семафор.** `maxConcurrent` снижен с 4 до 2, очередь с 32 до 8 — не из-за памяти
  (её стало меньше), а из-за пула libuv: четыре деривации по ~0.1 с занимали бы все
  четыре потока, и обработка картинок ждала бы за логинами.
- **Rehash-on-login.** Контракт адаптера получил `rehashUserPassword` — отдельный
  метод, потому что запись обязана НЕ поднимать поколение и НЕ рвать сессии: иначе
  вход выбрасывает сам себя тем cookie, который только что выдал. Условие записи —
  прежний хеш плюс поколение плюс активность. Деривация идёт оппортунистической формой
  шлюза: при занятых слотах рехеш пропускается, а не встаёт в очередь впереди тех, кто
  ждёт входа. Решение обновлять — проверка доминирования, а не «параметры отличаются»:
  последнее понизило бы хеш, посчитанный более дорогими параметрами.
- **Найденная связь, которой в разборе не было.** Признак «пароль всё ещё дефолтный»
  считается сравнением строк прямо в запросе сессии, поэтому сидовый хеш обязан быть
  написан нынешними параметрами: отстань он от них — первый вход дефолтного
  администратора перехешировал бы строку, сравнение перестало бы совпадать, и
  предупреждение погасло бы при живом дефолтном пароле. Записано в контракте рядом с
  флагом.
- **Вес редактора.** `vanilla-jsoneditor` и `json-editor-vue` сняты; подсветка
  собрана своим лексером без зависимостей (prismjs не понадобился: его 3.7 КБ шли бы
  с HTML-строкой в `v-html`, а токены-текстовые-узлы такой границы доверия не создают).
  Поверхность редактора: **656 → 349 КБ gzip**, ушёл вендорный чанк на 309 КБ вместе
  с `ajv`, `jmespath`, `json-source-map` и `natural-compare-lite` из production-дерева.
  Бюджет в `scripts/bundle-budget.mjs` считает редактор ПРИРОСТОМ над published, а не
  суммой: иначе рост entry съедал бы его запас. Скрипт отказывается, когда выборка
  поверхности пуста — иначе переименование домена сделало бы бюджет вечно зелёным.
- **Подсветка одноцветная, и это замер, а не вкус.** Синие ключи дали 4.08:1 на фоне
  сайдбара в тёмной теме (нужно 4.5), а одним цветом обе темы не закрыть: светлая
  требует яркости ниже 0.18, тёмная выше 0.27. Цветной акцент потребует пары
  AA-безопасных переменных в общей палитре — это решение о палитре, не о редакторе.
- **Мимо счёта:** редактор JSON в интерфейсе достижим только через свойство типа
  `object`, а его не объявляет ни один блок пакета — поэтому в e2e-фикстуре появилось
  такое свойство, и axe-проверка состояния редактора теперь его действительно видит.

### Этап 3. П2 — остаток

Двадцать семь пунктов. Радиус ограничен, поэтому порядок задаёт удобство: сначала
то, что трогает файл, уже открытый по другой причине. Отдельного захода просит
«Загрузка файла собирается в памяти целиком» — решение принято в пользу потоковой
загрузки, и это переписанный путь загрузки, а не правка константы. «Осиротевшие
объекты хранилища некому убрать» делается одной командой на два префикса — медиа
и аватары.

**Выход:** `p2-defects.md` пуст.

### Этап 4. i18n одним проходом

Девять пунктов — одна механика: продуктовый текст уезжает в
`src/runtime/locales/`. Проход широкий (сайдбар, published-рендер, редактор текста,
кит), поэтому идёт отдельно от правок логики: иначе диффы перестают читаться.
Русское описание в `createError` — здесь же: оно пересекает HTTP-границу и видно
интегратору.

**Выход:** `i18n.md` пуст; из русского текста в `src/` остались только таблицы
транслитерации — они данные, а не текст.

### Этап 5. Мёртвый код (П3) одним заходом

Тридцать три пункта, поведение не меняется — значит один заход по домену и крупные
коммиты. Строго после этапа 3: часть «мёртвого» кода — это то, что дефект должен
был использовать, и до починки снимать его нельзя.

**Выход:** `p3-dead-code.md` пуст, `npm run knip:check` без новых сообщений.

### Этап 6. Дубли и правила (П4, П5)

Восемьдесят пунктов — это фон, а не спринт. Правило отбора: берётся то, что
трогает файл, уже открытый по другой причине. Отдельного захода просят только
крупные — `BlockGrid.vue` за потолком размера SFC, интерфейсы пропсов из
одиннадцати SFC, две функции `buildGridTemplateRows` с одним именем и разным
поведением.

**Выход:** оба файла пусты, `deps:check` и `type-check` зелёные без исключений.

### Попутно, не этапом

- **Разъехавшиеся тексты** ([stale-text](stale-text.md)) закрываются в том же
  коммите, что и правка рядом. Отдельного захода просят только те, что вводят в
  заблуждение: README про миграции, которых больше нет, и warning резолвера backend,
  обещающий отказ всего `/api/bricks/**`.
- **Не построенное** ([features](features.md)) — продуктовая дорожка, встаёт между
  этапами по решению владельца. Внутри порядок задан только у двух пунктов:
  предпросмотр сниппета выдачи идёт до предпросмотра карточки в соцсетях, они
  считают адрес одним composable.
