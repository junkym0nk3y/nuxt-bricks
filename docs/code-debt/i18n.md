# i18n-долг

Продуктовый текст, зашитый в код. Закрывается ключами локалей
(`src/runtime/locales/{ru,en}.json`), а не переводом строки на английский: перевод
меняет один язык на другой, а нужен выбор языка. Индекс — [README.md](README.md).

Этот трек нельзя брать «по порядку» вместе с приоритетами: каждый пункт — решение о
продуктовом тексте, а не правка кода. Часть строк ещё и видна пользователю пакета,
то есть добавление ключа меняет его интерфейс.

---

## 1. Русское описание в `createError` пересекает HTTP-границу

**Файл:** `src/runtime/server/utils/bricksComponents.ts:67`

```ts
data: {
    description: 'Убедитесь, что brick-файлы этой категории существуют в components/',
},
```

Единственный русский текст, оставленный в `src/` намеренно: он уходит в теле ответа
404 и может отрендериться у потребителя, то есть это продуктовый текст, а не
dev-сообщение. Перевод строки на английский ничего не решает — её место в локалях.

Про достижимость: единственный потребитель `data.description` в модуле сейчас
отсутствует (`grep` по `src/runtime` находит только описание механизма в
`publish/utils/requestErrors.ts:204`), но текст всё равно уезжает в ответе, и
приложение-потребитель вправе его показать.

Это же место названо исключением в `.claude/rules/comments.md` — при закрытии
пункта запись оттуда снять.

## 2. Захардкоженный текст интерфейса в трёх местах кита

**Файлы:** `src/runtime/modules/ui/inputs/BricksToolbarColorPicker.vue:187`,
`inputs/BricksToolbarEditableSelect.vue:278`, `feedback/BricksToast.vue:178`

Два русских текста ошибки рисуются в интерфейсе: «Неверный HEX» и «Некорректное
значение». Второй файл при этом уже использует `t()` для плейсхолдера, первый
`useI18n` не подключает вовсе.

Третье место: у `ToastClose` доступное имя зашито по-английски
(`aria-label="Close"`) при существующем ключе `bricks.common.close` (`ru.json` —
«Закрыть»). То есть на русской локали скринридер читает крестик тоста по-английски.

## 3. i18n-долг сайдбара: подписи и плейсхолдеры мимо словарей

**Файлы:** `builder/shell/sidebar/components/BuilderShellSidebarPublishView.vue:387,392,357,466`,
`sidebar/components/BuilderShellSidebarPropertyEditors.vue:354,357`,
`sidebar/components/BuilderShellSidebarNavigationEditor.vue:118`,
`property-editors/BuilderShellSidebarPropertyMediaPicker.vue:20,73`,
`property-editors/BuilderShellSidebarPropertyJsonEditor.vue:28`,
`sidebar/utils/variantBuilders.ts:129,174`

Хардкод английского UI-текста рядом с полями, которые i18n используют: `Layout`
(подпись и `aria-label`), `URL Prefix`, `OG/Twitter image`, `HTML ID`, плейсхолдеры
`my-section`, `blog`, `spb`, `#section-id`, `alt="Preview"`, дефолты пропов
`label: 'Media'` и `label: 'JSON'`, а в билдерах вариантов —
`Enter ${property.label || property.name}` и `item1, item2, item3`.

Часть из этого попадает в интерфейс потребителя рядом с переведёнными строками: в
форме публикации `URL Prefix` стоит вплотную к `t('bricks.publish.subdomain')`.

## 4. i18n-долг published-рендера

**Файлы:** `render/components/TheRenderer.vue:107-108`,
`render/components/RendererPlaceholder.vue:8-9`, `render/pages/[pagename].vue`
(баннер превью и заглушка загрузки)

Русский текст, который видит **посетитель опубликованной страницы**: заголовок и
описание заглушки недоступного компонента (в двух местах — дефолты
`RendererPlaceholder` и явные значения из `TheRenderer`), «Режим превью», «Закрыть
превью», «Загружаем страницу...».

Отдельный край: шапка `RendererCloseButton` объясняет вынос доступного имени наружу
тем, что «зашитая строка годилась бы ровно для одного языка», — а единственный
вызывающий передаёт как раз зашитую русскую строку. Рационал верен по устройству
(компонент языка не знает), но выигрыш от него сегодня нулевой и появится только
вместе с i18n рендера.

Из всех пунктов трека этот — самый видимый снаружи: остальные показываются редактору,
этот — конечному посетителю сайта потребителя.

## 5. Хардкод русского UI-текста в редакторе текста

**Файлы:** `text-editor/components/TextEditorArea.vue` (сообщение об ошибке загрузки
редактора), `text-editor/components/TheTextEditorModal.vue` (кнопка «Готово»)

Рядом в тех же файлах всё остальное уже идёт через `t(...)`, включая заголовок
модалки и подписи кнопок тулбара, поэтому эти две строки — не стиль, а пропуск.

## 6. `Baseline` — единственная подпись попавера без ключа локали

**Файл:** `text-editor/components/TextEditorImageFloatPopover.vue` (`VALIGN_OPTIONS`,
разметка подсказки)

У двух опций из трёх `label` — ключ локали (`bricks.textEditor.alignMiddle`,
`bricks.textEditor.alignTop`), у первой — литерал `'Baseline'`. Из-за этого в
разметке пришлось развести случаи тернарником:
`option.value === 'baseline' ? option.label : t(option.label)`.

Ключ локали убрал бы и литерал, и тернарник разом — то есть здесь долг ещё и
усложняет код.

## 7. Русский фоллбэк рядом с ключом локали

**Файл:** `builder/core/composables/useModalOptions.ts:42`

`i18n?.t('bricks.properties.modalDisabled') ?? 'Отключено'`. Ключ есть в обеих
локалях (`ru.json:180` — «Отключено», `en.json:180` — «Disabled»), но при недоступном
`$i18n` селектор покажет русскую подпись пользователю с любым языком.

Это единственное такое место в `src/runtime/modules` (греп по `?? '<кириллица>'`
даёт одно вхождение).

## 8. Русский продуктовый fallback в `unknownErrorMessage`

**Файл:** `builder/publish/utils/requestErrors.ts:62`

`unknownErrorMessage` зовёт `translate('bricks.common.unknownError', 'Неизвестная
ошибка')`, то есть держит русский текст продуктового сообщения прямо в коде.

Двадцатью строками ниже `timeoutMessage` — единственный второй потребитель
`translate` в файле — прямо объясняет, почему fallback-строк не пишут: «дублировать
текст локали в коде незачем, а вне Nuxt-контекста `translate` отдаёт сам ключ». Оба
аргумента применимы и здесь, а ключ `bricks.common.unknownError` в обеих локалях
есть.

Про достижимость: `translate` начинается с `useNuxtApp()`, который вне
Nuxt-контекста бросает, — то есть fallback срабатывает только в контексте, где
`$i18n` не зарегистрирован. Ветка почти мёртвая, а русский текст в ней —
единственный в домене.

## 9. Дефолт текста блока Text разный в двух местах

**Файлы:** `layouts-blocks/components/blockText.definition.ts`
(`'<p>Введите текст</p>'`), `components/BlockText.vue` (`withDefaults`,
`'<p>Начните вводить текст...</p>'`)

Оба литерала русские, но они ещё и разные. Дефолт компонента виден только там, где
блок отрисован без пропа `content`, то есть в обход definition — то есть либо это
мёртвая ветка, либо на published пользователь увидит другой текст, чем в билдере.

При закрытии пункта тогда же и решится, нужен ли второй дефолт вообще.
