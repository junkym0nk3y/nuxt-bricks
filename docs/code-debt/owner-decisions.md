# Решения владельца, не правки

Не задачи. Места, где код работает, а вопрос в том, что считать правильным: у них
нет ответа, выводимого из самого кода. Пока решение не принято, брать их в работу
нельзя — любая правка здесь будет продуктовым решением, спрятанным в рефакторинге.

Индекс — [README.md](README.md).

---

## 1. `v-html` статьи документации минует `sanitize` без записанной причины

**Файлы:** `builder/documentation/components/TheBuilderDocumentationModal.vue:126`,
источник HTML — `useMarkdownRenderer.ts` (`markdown-it` с `html: true`)

Правило `AGENTS.md` («любой недоверенный HTML/SVG перед `v-html` пропускать через
`common/utils/sanitize/`») читается безусловно, а здесь `v-html` получает результат
`markdown-it`, включённого с `html: true`, то есть сырую разметку из `.md` пропускает
насквозь.

Недоверенного источника при этом нет: статьи приезжают build-time глобом по
`docs/guide/**` из самого пакета, пользовательский ввод в этот путь не попадает.

**Вопрос не в поведении, а в том, что причины в коде не написано:** следующий
читатель увидит `v-html` без санитайза и без объяснения, а рядом в `layouts-blocks`
те же места снабжены хотя бы lint-директивами.

**Решить:** писать заметку с причиной или всё-таки прогонять через `sanitize`.
Заметку нельзя добавить «по ходу» — это утверждение о безопасности, и оно должно
быть чьим-то решением.

## 2. Копия страницы не освежает список, а публикация освежает

**Файл:** `builder/publish/utils/currentPageWrite.ts` (`runPublishPage` против
`runSaveCurrentPageAsCopy`)

Обе операции создают страницу одним и тем же `publishPageRequest`. `runPublishPage`
после успеха запускает `refreshPagesAfterPublish` и объясняет это тремя абзацами;
`runSaveCurrentPageAsCopy` ограничивается `syncPageInList`, и её JSDoc называет это
намеренным («сама синхронизирует список, без `loadAllPages()`»).

Дыры в пути копии нет — она синхронизируется полным ответом POST, а на таймауте
запускает то же восстановление. **Лишним выглядит безусловный detached refresh после
успеха `runPublishPage`:** его собственный JSDoc прямо говорит, что результату
создания эти данные не нужны.

То есть кандидат на снятие — не отсутствующий запрос у копии, а присутствующий у
публикации. Снимать его — решение о том, насколько свежим должен быть список после
публикации.

## 3. Warning резолвера backend обещает отказ всего `/api/bricks/**`

**Файл:** `src/module-backend-config.ts:50-53, 81-85`

Оба warning-а говорят, что без URL «/api/bricks/\*\* будет отвечать ошибкой». Это
шире правды: liveness-проба (`health/index.get.ts` — «checks no dependencies») и
ручка манифеста компонентов (читает server asset) от data backend не зависят вовсе.
Отказ касается data-backed и editorial-операций плюс readiness.

**Почему не правится само:** это **сообщение, которое читает интегрирующий
разработчик**, а не комментарий. Сузить его область — решение о содержании
продуктового текста. Связанная формулировка в `src/types/module.d.ts:108-113` была
комментарием и потому уже исправлена — то есть тип и сообщение сейчас говорят разное,
и это ждёт решения.

## 4. Сообщение CLI о drift предписывает forward-миграцию, а проект правит базовую

**Файл:** `src/cli/bricks-migrate.mjs:243-245`

Сообщение нормативно: выпущенные миграции не редактируются, изменение оформляется
новой forward-миграцией. Внутренняя процедура проекта обратная (`AGENTS.md`: правка
`migrations/0001_init.sql`, тот же DDL руками в живую БД, пересчёт строки реестра),
потому что пакет не опубликован и потребитель базы один.

Противоречия в коде нет — адресаты разные, сообщение видит интегрирующий
разработчик. **Но перед публикацией стоит убедиться, что README не выдаёт внутреннюю
процедуру за рекомендуемую.**

## 5. Домен документации держит реактивное состояние в модуле — против паттерна соседа

**Файлы:** `builder/documentation/composables/useDocumentationArticles.ts:26-27`
(`articleTitles`, `loadedTitlePrefixes`), `useMarkdownRenderer.ts:13-14`
(`mdInstance`, `isLoading`)

Соседний домен объясняет прямо противоположное решение и говорит, чем опасен
обратный выбор: `useTemplatesData.ts:27-37` — «модуль-глобальный промис на сервере
общий для ВСЕХ запросов процесса», и поэтому дедупликация и счётчик правок сидят в
`WeakMap` по экземпляру приложения Nuxt. Домен документации сделан наоборот: кэш
заголовков (`ref`), набор прочитанных префиксов (`Set`) и флаг загрузки библиотеки
(`ref`) объявлены на уровне модуля, то есть в одном серверном процессе общие для всех
запросов.

**Ущерба сегодня нет, и это важно записать честно:** содержимое кэша — build-time
статика (`import.meta.glob` по `docs/guide/**`), для всех запросов одинаковая. У двух
видов состояния разные законные сроки жизни: авторизованный список шаблонов обязан
быть request-scoped, а кэш неизменяемой build-time статики и экземпляр `MarkdownIt`
process-wide не ломают ничего и экономят повторную работу. То есть сравнение с
`useTemplatesData` показывает не дефект, а разницу предметов.

Оставлено как заметка для того, кто соберётся давать `isLoading` живого читателя
(сейчас он мёртв, см. [П3](p3-dead-code.md)): **вот с этого момента флаг придётся
переносить в `WeakMap`.**

## 6. `test/README.md` отстал от состава спеков

**Файл:** `test/README.md`

Файл документирует каждый спек по имени, список расходится с диском (216 файлов
`*.spec.ts`), и ничем это не проверяется.

**Отложено решением владельца:** набор тестов признан избыточным, планируется срез
порядка 90%, и синхронизация списка обесценится вместе с вырезанными спеками. После
сокращения дефолт — заменить пофайловый список описанием доменов, чтобы новый спек не
требовал правки README.

Пока срез не сделан, тот же порядок держит и пороги покрытия: ставить их до сокращения
нельзя (см. «Хвосты релизного гейта» в
[готовности к публикации](release-readiness.md)).

## 7. `as unknown as` в тестах: узаконить исключение или вычистить

**Где:** `test/**`, запрет — `.claude/rules/typescript.md`

Долг растёт: было 16 совпадений в 13 файлах, стало **30 в 21 файле**. Запрет в правиле
сформулирован без оговорок про `test/`, и ревью по ходу работы снимало каждое новое
приведение — то есть де-факто правило на тесты распространили, но исторические
остались.

**Вопрос:** вычищать их одной отдельной уборкой или узаконить исключение для `test/` в
самом правиле. Оба варианта законны; сегодняшнее состояние — «правило есть, но
соблюдается только для нового кода» — хуже любого из них, потому что не читается по
самому правилу.

## 8. Даты двенадцати карточек версий в макете восстановлены, а не перенесены

**Где:** файл дизайн-системы `FsPQKxtsHrbJiyiyal9ZlR`, карточки версий

При переводе карточек на компонент подпись бралась из первого текстового узла карточки,
а им оказались плашка «Текущая» и заглушка «Без снимка»; исходные фреймы к моменту
обнаружения были удалены. Сейчас у шести карточек стоит `01.08.2026 15:10` (значение
прочитанного образца) и у шести `29.07.2026 18:30` (придуманное демо-значение).

Данные демонстрационные, на код не влияют. **Если владелец помнит исходные — поправить,
иначе оставить как есть.** Записано, чтобы расхождение не всплыло как дефект синхронизации
макета.
