**Связки, на которых держится синк:**

- **Переменные ↔ CSS-переменные.** Каждая Figma-переменная несёт Code syntax (WEB):
  `color/base/900` → `var(--bricks-base-900)`, `radius/sm` → `var(--border-radius-sm)`.
  В Dev Mode Figma отдаёт сразу имя переменной из кода. Коллекция Color — 2 мода (Light/Dark) = `:root` / `.bricks-dark`.
- **Компоненты ↔ исходники.** В description каждого компонента — путь к `.vue`-файлу
  (Code Connect недоступен на Pro-тарифе, description его заменяет).
- **Rem-модель.** В макетах 1px = 0.1rem кода (билдер форсирует `html { font-size: 10px }`).
  Все размеры кратны 2px (= 0.2rem). Читая макет: `14px → 1.4rem`, `36px → 3.6rem`.

## 2. Design → Code: перенос правок из макета в проект

Основной сценарий. Правишь макет → кидаешь Клоду ссылку → он переносит в код.

### Как дать ссылку на правку

В Figma: выделить изменённый фрейм/компонент → правый клик → **Copy link to selection**.
Ссылка содержит `node-id` — по нему Клод прочитает именно этот узел.

### Примеры промптов

```text
Я поменял в макете Button: скругление и паддинги — вот ссылка <url>. Перенеси в код.

В макете Builder-экрана перекрасил тулбар и увеличил сайдбар до 360 — синхронизируй
TheBuilderShellToolbar.vue и TheBuilderShellSidebar.vue: <url>

Добавил в макет новый вариант Toast (warning) — сделай его в BricksToast.vue: <url>
```

### Что Клод делает при переносе

1. Читает узел (`get_design_context` / `get_screenshot` / `get_metadata` по node-id).
2. Сравнивает с текущим кодом компонента (путь берёт из description).
3. Переводит значения в конвенции проекта:
    - px → rem (÷10), кратность 0.2rem;
    - цвета → **только** `var(--bricks-*)` по привязанной переменной (не hex!);
    - тени → `var(--shadow-*)`, радиусы → `var(--border-radius-*)`;
    - CSS Modules, SCSS-нестинг — по `.claude/rules/styles.md`.
4. Прогоняет `vue-tsc` + `oxlint`, показывает diff.

### Правила в макете, чтобы перенос был точным

- **Красить только переменными.** Если нужен новый цвет — сначала добавить его в коллекцию
  Color (оба мода + Code syntax), затем использовать. Голый hex в макете = Клод спросит,
  каким токеном это должно быть.
- **Не отвязывать инстансы** (detach). Отвязанный инстанс теряет связь с компонентом,
  и правка перестаёт быть «правкой компонента X».
- **Размеры кратны 2px.** 15px в макете → в коде станет 1.4rem или 1.6rem (Клод округлит и скажет об этом).
- **Новый компонент — новая страница** (конвенция файла), в description — предполагаемый путь в `ui/`.
- Правки **вариантов** делать в самом component set, а не в инстансах на экранах.

## 3. Code → Design: синк макета после правок кода

Обратный сценарий: код изменился (новый вариант, другой цвет, новый компонент) — макет отстал.

```text
Я добавил в BricksButton вариант "warning" — добавь его в Figma-сет Button.

Поменял --bricks-primary на #1d4ed8 в _variables.scss — обнови переменную в Figma (оба мода проверь).

Добавил компонент BricksBadge в ui/ — перенеси в библиотеку (страница + варианты + биндинги).
```

Клод читает исходник и обновляет макет теми же инструментами (use_figma), сохраняя биндинги.
После крупных правок кода можно попросить **сверку**: «пройдись по компонентам X, Y и скажи,
где макет разошёлся с кодом» — получите отчёт-диff без правок.

## 4. Дизайн новых фич до кода

Библиотека позволяет собирать новые экраны/блоки из готовых инстансов:

```text
Собери в Figma макет модалки "Настройки SEO" из компонентов библиотеки:
Input для title/description, Tags Editor для ключевых слов, кнопки внизу.
```

→ утверждаете макет глазами → «теперь реализуй это в коде» → Клод пишет `.vue` по макету,
уже зная, какие инстансы каким компонентам соответствуют. Это самый дешёвый путь
«придумать → посмотреть → реализовать» без выброшенного кода.

Иконки для новых макетов Клод берёт со страницы 🔣 Icons — это точные векторы из
`@kalimahapps/vue-icons`, вставка = точное соответствие будущему `<BricksIcon icon="…">`.

## 5. Тёмная тема

Коллекция Color двухмодовая. Чтобы посмотреть любой экран/компонент в тёмной теме:
выделить фрейм → правая панель → Layer → иконка режимов → Color: Dark.
Инвариантные поверхности (`surface/dark-preview`, `surface/workspace`) и канвас-контент
не меняются — как в реальном билдере (`.bricks-canvas` reset).
