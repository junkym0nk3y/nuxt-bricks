# Спринт комментариев: журнал работ

Закрытые этапы спринта `comments-sprint.md`. Этап удаляется из плана и появляется
здесь. Находки ревью — в `comments-sprint-findings.md`.

---

## Этап 0 — эталон и гейт (2026-08-21)

### Эталон стиля

Переведены **целиком** как образец регистра:

- `src/runtime/modules/common/utils/apiRequestPolicy.ts` — 16 блоков, включая
  шапку файла и три длинных рационала (`CLIENT_OWNED_REQUEST_OPTIONS`,
  `applyApiRequestTimeout`, `normalizeRequestAbortError`);
- `src/runtime/modules/persistence/server/utils/requestBodyLimits.ts` — 18 блоков,
  включая шапку (три барьера ingress-контроля), блок бюджета и
  `withMultipartFormData` (почему форма отдаётся колбэком, а не возвращается).

Файл переводится целиком, а не блоками: полупереведённый файл читается хуже любого
из двух однородных вариантов, и по нему невозможно сказать, дошла ли до него
работа. Правило действует на все этапы.

Что зафиксировано эталоном:

- структура длинного блока сохраняется дословно: решение → отброшенная
  альтернатива → дефект, который к этому привёл. Абзацы не сливаются;
- нормативная формулировка остаётся нормативной, а не превращается в описание;
- капитализация как выделение переносится (`ОДНОВРЕМЕННО` → `SIMULTANEOUSLY`,
  `ЗАЯВЛЕННЫЙ` → `DECLARED`);
- орфография американская, точки в конце однострочного JSDoc нет;
- **после дословного переноса обязателен редакторский проход.** Буквальность
  сохраняет структуру и нюанс, но оставляет кальки, а дважды в этом заходе
  перевернула технический тезис (находки 0.17, 0.18). Проза комментария
  переносится по ширине ~80, руками: prettier комментарии не переформатирует;
- дублировать рационал соседнего файла нельзя: вместо копии — ссылка на файл, где
  он живёт (так закрыта находка 0.1);
- обратные кавычки вокруг идентификаторов, версий библиотек и путей сохраняются.

### Гейт приёмки

`npm run comments:check`, пять модулей в `scripts/`:

| Файл                         | Ответственность                                                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `comment-scanner.mjs`        | лексер: один табличный сканер на js/ts, css/scss, sql, yaml, `#`-конфиги, html                |
| `comment-lines.mjs`          | что должен файл: комментарии по секциям, литералы, dev-сообщения, имена кейсов, проекция кода |
| `comment-sprint-areas.mjs`   | область спринта: перечисление файлов, карта путей на этапы, `done`, постоянные исключения     |
| `comment-diff-check.mjs`     | режим `--diff`: сравнение проекций кода двух ревизий                                          |
| `comment-language-check.mjs` | CLI и отчёт по областям                                                                       |

Команды:

```
npm run comments:check                              # отчёт по всем областям
npm run comments:check -- --area=1                  # закрытие этапа: падает при любом остатке
npm run comments:check -- --area=21+22 --metric=comments   # закрытие этапа по одному счётчику
npm run comments:check -- --list                    # каждая строка-нарушитель
npm run comments:check -- --diff                    # рабочее дерево против HEAD: только комментарии
npm run comments:check -- --json                    # машинный отчёт
```

Колонки отчёта:

| Колонка       | Что считает                                                                                 | Валит гейт |
| ------------- | ------------------------------------------------------------------------------------------- | ---------- |
| `ru comments` | кириллические строки комментариев                                                           | да         |
| `tpl/style`   | комментарии, оставшиеся в `<template>`/`<style>` и `.scss` (кроме lint-директив)            | да         |
| `literals`    | кириллица внутри шаблонных литералов                                                        | нет        |
| `gated`       | те же литералы в файлах генерируемого вывода — `module-scss.ts`, два `*Css.ts`, SQL-адаптер | да         |
| `ru msgs`     | кириллица в аргументах `throw`, `new Error`, `createError`, `console.*`                     | да         |
| `ru titles`   | русские имена кейсов `describe`/`it`/`test`, включая табличные `it.each`                    | да         |

Литералы информационны потому, что кириллица в шаблонном литерале бывает законной
фикстурой. Но у четырёх файлов это генерируемый вывод — `module-scss.ts` пишет
шапку в SCSS-файл **внутри проекта потребителя**, — и оставить их вне гейта значило
бы дать закрыть этап с самым заметным русским текстом пакета.

Как закрывается этап: `--area=<id>` показывает ноль → `done: true` у этой области
в `comment-sprint-areas.mjs`. После этого вернувшийся русский комментарий валит
уже обычный прогон без флагов. Этапы, делящие одно дерево (21 и 22 — `test/`),
закрываются по метрикам: `done: ['comments']`, проверка — `--metric=comments`.

### Решения по гейту

- **Состояние-машина, не регексп.** Три ловушки из плана проверены на реальном
  коде: продолжения многострочных блоков считаются (у них нет префикса);
  литерал регекспа в `persistence/server/utils/fileSignatures.ts:29`
  комментарием не считается (иначе репо-широкий strip сломал бы валидацию
  загрузки SVG); русские комментарии внутри шаблонных литералов найдены во всех
  трёх файлах плана (`containerCss.ts:75+`, `deviceVisibilityCss.ts:53`,
  `postgresAuthAdapter.ts:67-70`) и выведены отдельной колонкой, а не в гейт.
- **`--diff` доказывает, что логика не менялась — сравнением проекций.** Файл
  проецируется на свой код (символы комментариев забиваются пробелами, пустые
  строки отбрасываются, остальные обрезаются) в двух ревизиях, и проекции обязаны
  совпасть. Слабая версия проверки — «изменённая строка является строкой
  комментария» — пропускала правку кода на строке с хвостовым комментарием
  (находка 0.5), то есть не делала ровно того, ради чего существует. Заодно
  проекция убрала разбор unified diff целиком: хватает
  `git diff --name-status`. Пути вне области спринта (`docs/**`, `PAPERCUTS.md`)
  пропускаются со счётчиком, а не валят проверку; добавленный или удалённый файл
  комментарной правкой быть не может и сообщается как нарушение.
- **Гейт валит только области с `done: true`** — иначе он был бы красным весь
  спринт. Флаг `--area` — исключение: выбранная область обязана быть чистой.
- **Непокрытые картой пути — ошибка гейта.** Такой файл иначе остался бы русским
  навсегда, ни разу не показавшись как работа. Нашёлся ровно один
  (`src/runtime/types.d.ts` — реэкспорт типов `common`, комментариев нет), отдан
  области 1.
- **Область скана — по имени файла, не только по расширению.** Иначе
  `.gitattributes` с двумя русскими строками не сканировался вовсе (находка 0.7).
- **Имена кейсов разбираются, а не ищутся регекспом.** У `it.each([...])('имя %s')`
  заголовок — первый аргумент второго вызова; регексп недосчитывал 26 имён
  (находка 0.6).
- **Директивы инструментов** (`eslint-disable`, `stylelint-disable`, `#region`
  и прочие) распознаются по содержимому, а не по номерам строк из плана: номера
  уезжают с первой же правкой файла. Allow-list по пути один —
  `assets/scss/common/_normalize.scss` (атрибуция MIT вендоренного кода).
- **Пять модулей, а не один файл.** В одном получалось 1284 строки против
  `oxlint max-lines: 500`. Границы по ответственности, не по размеру; каждый файл
  остался в пределах 500 строк и после правок ревью.
- **Проекция кода щадит прозу и уважает отступы.** Локальный `README.md` — текст
  целиком, кода в нём нет, поэтому он проецируется в пустоту (иначе этап 20 не
  подтвердить). У `yaml` и `#`-конфигов снимается только хвостовой пробел: смена
  отступа там меняет документ, а не форматирование.
- **`process.exitCode` вместо `process.exit()`.** При выводе в пайп немедленный
  выход обрезал буфер stdout, и JSON-отчёт рвался посреди строки.

### Верификация

- `test/scripts/commentScanner.spec.ts` — 14 кейсов: ловушки плана плюс регресс на
  каждую находку ревью.
- **Диффтест против парсера TypeScript** по всем 739 `.ts`-файлам репозитория:
  ни одного пропущенного комментария. 44 расхождения — все в сторону «мой сканер
  нашёл, эталон нет», и все 44 строки несут маркер комментария: `ts.getLeadingCommentRanges`
  по границам узлов не видит хвостовых комментариев в объектных литералах и
  комментариев внутри цепочек вызовов. Голый `ts.createScanner` эталоном не
  годится вовсе — без `reScanSlashToken` он не распознаёт литералы регекспов и
  расстраивается на первом же.
- **Мутационная проверка `--diff`** двумя мутациями: обычная строка кода и код на
  строке с хвостовым комментарием. Обе валят режим с точным указанием
  разошедшейся строки проекции, откат восстанавливает. Вторая мутация до правки
  0.5 проходила.
- Числа парсера сошлись с числами планирования независимо (до перевода эталона):
  `common` 2002 против 2001, `persistence` 2460 против 2464, `server` 1143 против
  1142, `test` 3637 против 3630, имена кейсов 1996 против «около 2000»,
  `migrations` 153 против 152.
- Проверки: `type-check`, `el:check`, `format:check`, `sl:check`, `deps:check`,
  `knip:check`, `npm test` — зелёные.
- **Диффтест повторён после правок**: 753 файла (`.ts`, `.mjs`, `.cjs`), ноль
  пропусков; 48 расхождений — пробелы эталона, все несут маркер комментария.
- **Фактчек по ходу полного перевода**: `ofetch` установлен в 1.5.1, и обе
  прибитые ссылки на его внутренности сошлись дословно — `:261` действительно
  `if (!context.options.signal && context.options.timeout)`, а `:287-300` —
  `finally` со снятием таймера и начало чтения тела за ним. В
  `withMultipartFormData` подтверждены `sharp` на пути загрузки, три вызывающих с
  колбэком и `validate*`-хелперы (`validateAndOptimizeImage`, `validateVideo`),
  работающие по разобранной форме.
- **Ревью Codex, раунд 1** (gpt-5.6-sol high, свободное, 14 мин): восемь
  приёмочных разрывов в гейте и одно замечание по эталону. Все проверены на своей
  стороне — два воспроизведены мутацией, один по коду — и закрыты: находки
  0.5-0.7 и 0.9-0.15.
- **Ревью Codex, раунд 2** (по полному переводу, 4 мин): четыре пункта — два
  смысловых искажения, одна фактическая неточность и слой калек. Все подтверждены
  и закрыты: находки 0.16-0.19. Из шести предложенных формулировок пять взял
  дословно, одну поправил (замена теряла механизм chunked transfer). Вердикт
  раунда: «после редакторского прохода файлы смогут служить эталоном».

### Решения владельца по ходу этапа

- **Файл переводится целиком.** Частичный перевод (только шапка) отклонён.
- **Атрибуция MIT в `_normalize.scss:1-13` переводится.** «Оставить дословно» в
  плане означало «не удалять при чистке комментариев из стилей», а не «не
  переводить». Гейт уже считает её подлежащей переводу (этап 10), менять его не
  нужно.
