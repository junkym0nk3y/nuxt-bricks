# Спринт комментариев: журнал работ

Закрытые этапы спринта `comments-sprint.md`. Этап удаляется из плана и появляется
здесь. Находки ревью — в `comments-sprint-findings.md`.

## Этап 0 — эталон и гейт (2026-08-21)

### Эталон стиля

Переведены **целиком** как образец регистра:

- `src/runtime/modules/common/utils/apiRequestPolicy.ts` — 16 блоков, включая
  шапку файла и три длинных рационала (`CLIENT_OWNED_REQUEST_OPTIONS`,
  `applyApiRequestTimeout`, `normalizeRequestAbortError`);
- `src/runtime/modules/persistence/server/utils/requestBodyLimits.ts` — 18 блоков,
  включая шапку (три барьера ingress-контроля), блок бюджета и
  `withMultipartFormData` (почему форма отдаётся колбэком, а не возвращается).

Файл переводится целиком, а не блоками: полупереведённый файл читается хуже любого
из двух однородных вариантов, и по нему невозможно сказать, дошла ли до него
работа. Правило действует на все этапы.

Что зафиксировано эталоном:

- структура длинного блока сохраняется дословно: решение → отброшенная
  альтернатива → дефект, который к этому привёл. Абзацы не сливаются;
- нормативная формулировка остаётся нормативной, а не превращается в описание;
- капитализация как выделение переносится (`ОДНОВРЕМЕННО` → `SIMULTANEOUSLY`,
  `ЗАЯВЛЕННЫЙ` → `DECLARED`);
- орфография американская, точки в конце однострочного JSDoc нет;
- **после дословного переноса обязателен редакторский проход.** Буквальность
  сохраняет структуру и нюанс, но оставляет кальки, а дважды в этом заходе
  перевернула технический тезис (находки 0.17, 0.18). Проза комментария
  переносится по ширине ~80, руками: prettier комментарии не переформатирует;
- дублировать рационал соседнего файла нельзя: вместо копии — ссылка на файл, где
  он живёт (так закрыта находка 0.1);
- обратные кавычки вокруг идентификаторов, версий библиотек и путей сохраняются.

### Гейт приёмки

`npm run comments:check`, пять модулей в `scripts/`:

| Файл                         | Ответственность                                                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| `comment-scanner.mjs`        | лексер: один табличный сканер на js/ts, css/scss, sql, yaml, `#`-конфиги, html                |
| `comment-lines.mjs`          | что должен файл: комментарии по секциям, литералы, dev-сообщения, имена кейсов, проекция кода |
| `comment-sprint-areas.mjs`   | область спринта: перечисление файлов, карта путей на этапы, `done`, постоянные исключения     |
| `comment-diff-check.mjs`     | режим `--diff`: сравнение проекций кода двух ревизий                                          |
| `comment-language-check.mjs` | CLI и отчёт по областям                                                                       |

Команды:

```
npm run comments:check                              # отчёт по всем областям
npm run comments:check -- --area=1                  # закрытие этапа: падает при любом остатке
npm run comments:check -- --area=21+22 --metric=comments   # закрытие этапа по одному счётчику
npm run comments:check -- --list                    # каждая строка-нарушитель
npm run comments:check -- --diff                    # рабочее дерево против HEAD: только комментарии
npm run comments:check -- --json                    # машинный отчёт
```

Колонки отчёта:

| Колонка       | Что считает                                                                                 | Валит гейт |
| ------------- | ------------------------------------------------------------------------------------------- | ---------- |
| `ru comments` | кириллические строки комментариев                                                           | да         |
| `tpl/style`   | комментарии, оставшиеся в `<template>`/`<style>` и `.scss` (кроме lint-директив)            | да         |
| `literals`    | кириллица внутри шаблонных литералов                                                        | нет        |
| `gated`       | те же литералы в файлах генерируемого вывода — `module-scss.ts`, два `*Css.ts`, SQL-адаптер | да         |
| `ru msgs`     | кириллица в аргументах `throw`, `new Error`, `createError`, `console.*`                     | да         |
| `ru titles`   | русские имена кейсов `describe`/`it`/`test`, включая табличные `it.each`                    | да         |

Литералы информационны потому, что кириллица в шаблонном литерале бывает законной
фикстурой. Но у четырёх файлов это генерируемый вывод — `module-scss.ts` пишет
шапку в SCSS-файл **внутри проекта потребителя**, — и оставить их вне гейта значило
бы дать закрыть этап с самым заметным русским текстом пакета.

Как закрывается этап: `--area=<id>` показывает ноль → `done: true` у этой области
в `comment-sprint-areas.mjs`. После этого вернувшийся русский комментарий валит
уже обычный прогон без флагов. Этапы, делящие одно дерево (21 и 22 — `test/`),
закрываются по метрикам: `done: ['comments']`, проверка — `--metric=comments`.

### Решения по гейту

- **Состояние-машина, не регексп.** Три ловушки из плана проверены на реальном
  коде: продолжения многострочных блоков считаются (у них нет префикса);
  литерал регекспа в `persistence/server/utils/fileSignatures.ts:29`
  комментарием не считается (иначе репо-широкий strip сломал бы валидацию
  загрузки SVG); русские комментарии внутри шаблонных литералов найдены во всех
  трёх файлах плана (`containerCss.ts:75+`, `deviceVisibilityCss.ts:53`,
  `postgresAuthAdapter.ts:67-70`) и выведены отдельной колонкой, а не в гейт.
- **`--diff` доказывает, что логика не менялась — сравнением проекций.** Файл
  проецируется на свой код (символы комментариев забиваются пробелами, пустые
  строки отбрасываются, остальные обрезаются) в двух ревизиях, и проекции обязаны
  совпасть. Слабая версия проверки — «изменённая строка является строкой
  комментария» — пропускала правку кода на строке с хвостовым комментарием
  (находка 0.5), то есть не делала ровно того, ради чего существует. Заодно
  проекция убрала разбор unified diff целиком: хватает
  `git diff --name-status`. Пути вне области спринта (`docs/**`, `PAPERCUTS.md`)
  пропускаются со счётчиком, а не валят проверку; добавленный или удалённый файл
  комментарной правкой быть не может и сообщается как нарушение.
- **Гейт валит только области с `done: true`** — иначе он был бы красным весь
  спринт. Флаг `--area` — исключение: выбранная область обязана быть чистой.
- **Непокрытые картой пути — ошибка гейта.** Такой файл иначе остался бы русским
  навсегда, ни разу не показавшись как работа. Нашёлся ровно один
  (`src/runtime/types.d.ts` — реэкспорт типов `common`, комментариев нет), отдан
  области 1.
- **Область скана — по имени файла, не только по расширению.** Иначе
  `.gitattributes` с двумя русскими строками не сканировался вовсе (находка 0.7).
- **Имена кейсов разбираются, а не ищутся регекспом.** У `it.each([...])('имя %s')`
  заголовок — первый аргумент второго вызова; регексп недосчитывал 26 имён
  (находка 0.6).
- **Директивы инструментов** (`eslint-disable`, `stylelint-disable`, `#region`
  и прочие) распознаются по содержимому, а не по номерам строк из плана: номера
  уезжают с первой же правкой файла. Allow-list по пути один —
  `assets/scss/common/_normalize.scss` (атрибуция MIT вендоренного кода).
- **Пять модулей, а не один файл.** В одном получалось 1284 строки против
  `oxlint max-lines: 500`. Границы по ответственности, не по размеру; каждый файл
  остался в пределах 500 строк и после правок ревью.
- **Проекция кода щадит прозу и уважает отступы.** Локальный `README.md` — текст
  целиком, кода в нём нет, поэтому он проецируется в пустоту (иначе этап 20 не
  подтвердить). У `yaml` и `#`-конфигов снимается только хвостовой пробел: смена
  отступа там меняет документ, а не форматирование.
- **`process.exitCode` вместо `process.exit()`.** При выводе в пайп немедленный
  выход обрезал буфер stdout, и JSON-отчёт рвался посреди строки.

### Верификация

- `test/scripts/commentScanner.spec.ts` — 14 кейсов: ловушки плана плюс регресс на
  каждую находку ревью.
- **Диффтест против парсера TypeScript** по всем 739 `.ts`-файлам репозитория:
  ни одного пропущенного комментария. 44 расхождения — все в сторону «мой сканер
  нашёл, эталон нет», и все 44 строки несут маркер комментария: `ts.getLeadingCommentRanges`
  по границам узлов не видит хвостовых комментариев в объектных литералах и
  комментариев внутри цепочек вызовов. Голый `ts.createScanner` эталоном не
  годится вовсе — без `reScanSlashToken` он не распознаёт литералы регекспов и
  расстраивается на первом же.
- **Мутационная проверка `--diff`** двумя мутациями: обычная строка кода и код на
  строке с хвостовым комментарием. Обе валят режим с точным указанием
  разошедшейся строки проекции, откат восстанавливает. Вторая мутация до правки
  0.5 проходила.
- Числа парсера сошлись с числами планирования независимо (до перевода эталона):
  `common` 2002 против 2001, `persistence` 2460 против 2464, `server` 1143 против
  1142, `test` 3637 против 3630, имена кейсов 1996 против «около 2000»,
  `migrations` 153 против 152.
- Проверки: `type-check`, `el:check`, `format:check`, `sl:check`, `deps:check`,
  `knip:check`, `npm test` — зелёные.
- **Диффтест повторён после правок**: 753 файла (`.ts`, `.mjs`, `.cjs`), ноль
  пропусков; 48 расхождений — пробелы эталона, все несут маркер комментария.
- **Фактчек по ходу полного перевода**: `ofetch` установлен в 1.5.1, и обе
  прибитые ссылки на его внутренности сошлись дословно — `:261` действительно
  `if (!context.options.signal && context.options.timeout)`, а `:287-300` —
  `finally` со снятием таймера и начало чтения тела за ним. В
  `withMultipartFormData` подтверждены `sharp` на пути загрузки, три вызывающих с
  колбэком и `validate*`-хелперы (`validateAndOptimizeImage`, `validateVideo`),
  работающие по разобранной форме.
- **Ревью Codex, раунд 1** (gpt-5.6-sol high, свободное, 14 мин): восемь
  приёмочных разрывов в гейте и одно замечание по эталону. Все проверены на своей
  стороне — два воспроизведены мутацией, один по коду — и закрыты: находки
  0.5-0.7 и 0.9-0.15.
- **Ревью Codex, раунд 2** (по полному переводу, 4 мин): четыре пункта — два
  смысловых искажения, одна фактическая неточность и слой калек. Все подтверждены
  и закрыты: находки 0.16-0.19. Из шести предложенных формулировок пять взял
  дословно, одну поправил (замена теряла механизм chunked transfer). Вердикт
  раунда: «после редакторского прохода файлы смогут служить эталоном».

### Решения владельца по ходу этапа

- **Файл переводится целиком.** Частичный перевод (только шапка) отклонён.
- **Атрибуция MIT в `_normalize.scss:1-13` переводится.** «Оставить дословно» в
  плане означало «не удалять при чистке комментариев из стилей», а не «не
  переводить». Гейт уже считает её подлежащей переводу (этап 10), менять его не
  нужно.

### Решения по ходу

- **Таблица транслитерации `utils/slug.ts` не тронута** (66 кириллических ключей —
  запрет плана). Но переведённый комментарий над ней пришлось переписать без
  кириллических примеров: гейт считает кириллицу в строке комментария нарушением
  независимо от того, что это пример буквы. Пример назван кодовыми точками
  (U+0438 + U+0306 против U+0439).
- **Ссылки на файлы-планы спринтов убраны** по требованию `AGENTS.md`: три штуки
  (`docs/backend-connection-modes-plan-2026-07-12.md` — файла уже нет вовсе,
  «архитектурный аудит», «шаг B1», «Часть B»). Сам факт в каждом случае сохранён
  словами — находки 1.1-1.4.
- **Django из комментариев убран.** Слова `django` в репозитории нет; три
  комментария объясняли поведение «ответами Django backend», причём
  `case-transform` работает и на Postgres-пути. Сам проброс `csrftoken` →
  `X-CSRFToken` записан как кандидат в мёртвый код, логику не правил (находка 1.6).
- **Проекция кода в `--diff` научена не считать правкой кода переводимый текст
  вне комментариев** — иначе подтвердить `--diff` было нельзя ни для одного этапа
  с dev-сообщением (5, 7, 8, 9, 23), хотя план требует его для всех этапов кроме
  10, 22 и 24. Диапазоны (аргументы dev-вызовов, имена кейсов, комментарии внутри
  шаблонных литералов) выделены в новый модуль `scripts/comment-text-ranges.mjs` и
  сворачиваются в ничто; интерполяции `${…}` из них вырезаются — выражение внутри
  сообщения остаётся кодом. Подробности и проверка — находка 1.7.

### Ревью Codex, раунд 1 (gpt-5.6-sol high, свободное, 9 мин 18 с)

Шесть находок: четыре в итоговом отчёте и две по ходу, замеченные в логе задания до
его завершения. Все шесть воспроизведены на своей стороне и закрыты — 1.11-1.16.

Три из них — ослабление приёмки моей же правкой гейта, и это главный результат
раунда: правило имён кейсов срабатывало на `.test()` yup в продакшн-коде (1.11),
разрез по `${…}` был вторым неполным JS-сканером и падал на `${/}/.test(flag)`
(1.12), а правило dev-сообщений сворачивало все литералы выражения, включая ключи
локали и аргументы вложенных вызовов (1.13). Две последние Codex предъявил с
воспроизведением, и оба воспроизведения сошлись дословно.

Остальные три — по переводу: 112 однострочных JSDoc с точкой на конце (1.14),
разъехавшийся с кодом комментарий `parsePreviewVersionId` (1.15) и британское
`travelling` вместе с потерянной капитализацией `ID` (1.16).

Плюс список калек без номера находки — пять формулировок (`garbage is put out here`,
`the width goes out only through`, `the database has none of it`, `there is no
receiver for it`, `the volume of the template`) переписаны редакторским проходом.
Вердикт раунда по остальному: запрещённых ссылок на задачи и непереведённых русских
комментариев в `common` не найдено, кириллица осталась только в таблице
транслитерации и в локальных `README.md` этапа 20.

### Решение владельца: рационал остаётся в `.scss`

План велел вырезать из `.scss` все комментарии (329 строк колонки `tpl/style`), перенеся
SassDoc `public/**` в корневой README. При чтении файлов набралось ~150 строк рационала,
которого больше нигде нет и который подпадает под собственное правило плана «сначала
перенести, потом удалять»: две зоны reset'а с нормативным «новые правила только сюда, списки
держать синхронными», лестница z-index с двумя починенными ею дефектами, разбор переходов
(почему у view-switch фаза 140 мс, почему масштаб окна целит в `> *:not([role='dialog'])`,
почему canvas-flow без leave), кольца канваса, инвариантные поверхности. Переселять это
некуда: `<script>` у отдельно стоящей таблицы стилей нет, а корневой README — документация
потребителя, не место для внутренностей пакета.

Владелец решение изменил: **правило «секции стилей без комментариев» писалось для `<style>`
внутри SFC**, где рядом есть `<script>`; на самостоятельные таблицы стилей пакета оно не
распространяется. Рационал остался на месте и переведён, SassDoc `public/**` тоже остался
SassDoc'ом — иначе публичный SCSS-API пакета лишился бы документации в самом файле.

Гейт расширен под это решение: `MARKUP_COMMENT_ALLOWED` (Set из одного вендоренного
`_normalize.scss`) заменён предикатом `isMarkupCommentAllowed`, пропускающим весь префикс
`src/runtime/assets/scss/`. **Перевод не отменён** — кириллица в этих файлах валит гейт
по-прежнему; снята только колонка `tpl/style`.

### Три ловушки уехали к владельцам в коде, а не в README

План велел перенести «заодно» в README три предупреждения, удаление которых приглашает
причесать пакет и сломать его. У всех трёх нашёлся владелец в коде, а запрет спринта на
дубль рационала соседнего файла сильнее буквы «в README»:

- **шапка `bundle.scss`** (почему `fonts` не через `@use`) уже была написана в `src/module.ts`
  — там, где entry и регистрируется. Причём `module.ts` ссылался на копию («see bundle.scss»),
  то есть на текст, который этап и убирал (находка 10.2);
- **шапка `common/fonts.scss`** (имя `Inter` — строковый литерал) переехала к
  `useBricksConfig.ts`, на строку дефолта `defaultFont`. По дороге выяснилось, что перечень
  потребителей в ней неверен (находка 10.1);
- **порядок `@layer`** в `default.scss` переехал в кейс `test/module/styleIsolation.spec.ts`,
  который его и ассертит.

Ещё три дубля сняты по тому же правилу: блок длительности модалки повторял JSDoc computed
`rootStyle` у `BricksModal.vue` (10.3), разбор пары `pointer-events` + `inert` — шапку
`common/utils/transitionInert.ts` (10.4), предпосылка `display: contents` у масштаба окна —
шапку того же `BricksModal.vue` (10.12).

**Но переносить весь текст к владельцу оказалось перебором.** Ревью справедливо заметило,
что `bundle.scss` и `fonts.scss` — это места, где совершается опасная правка, и редактор,
удаляющий `@use`-запрет или переименовывающий `font-family`, до `module.ts` и
`useBricksConfig.ts` не дойдёт. В обоих файлах восстановлена **однострочная ссылка** на
владельца — ровно тот приём, которым с самого начала был решён `@layer` в `default.scss`.
Правило на будущее: ссылка ставится не там, где факт интересен, а там, где его нарушают.

момент: комментарий всё равно перечитывается целиком, а рядом стоит код, который его
опровергает.

### Правки текста по разъехавшимся комментариям

Две ошибки факта, и обе — не про свой домен, а про механику чужого слоя, причём обе
опровергаются экспериментом, а не чтением:

- **`useState` реактивен вглубь** (15.3). Комментарий объяснял замену состояния целиком тем,
  что точечная мутация внутри `useState` «не обязана оповещать подписчиков». В Nuxt `useState`
  — это `toRef` на `reactive({})`-объект payload, то есть объект внутри реактивен вглубь;
  прогон на самом vue показал, что и присваивание поля, и `push` в массив перезапускают
  эффект. Первая замена («список и статус меняются вместе») оказалась неверна тоже — её снял
  ревьюер, разбор в находке 15.13.
- **Комментарий перед корневым узлом не ломает fallthrough-атрибуты** (15.4). Компиляция
  шаблона через `@vue/compiler-dom` дала в dev флаг `DEV_ROOT_FRAGMENT` (2048), под который
  `renderComponentRoot` ищет единственного некомментарного ребёнка и применяет атрибуты к нему,
  а в prod комментарий вырезается и корень остаётся одиночным. Ложное обоснование снято, само
  решение (`aria-busy` на корне строки) осталось.

Плюс исправленная ссылка на несуществующий CLI провижининга учёток (15.10) и четыре снятых
дубля рационала (15.2, 15.5, 15.6 и дубль `isSubmitSealed`).

Закономерность этапа продолжает линию 14-го, но резче: **проверять надо не только «верен ли
комментарий», но и «проверяемо ли утверждение вообще»**. Обе ошибки факта — про поведение
фреймворка, обе выглядели правдоподобно и прошли бы любой редакторский проход; поймались они
только тем, что утверждение было переформулировано как опыт («мутируем поле — перезапустится
ли эффект?», «компилируем шаблон с комментарием — какой флаг у корня?»). Оба опыта — по десять
строк.

Второе наблюдение — про то, где живёт правда. Из шести находок по дублям **пять указывают в
`ui/`**: кит успел документировать и `muted`-против-`disabled`, и контраст тонов, и то, что
отступы пустого состояния задаёт вызывающий. Домен поздний, кит закрыт в этапе 2 — и
комментарии домена в основном пересказывают его же документацию.

**Расхождение конвенции точки, найденное по ходу.** Одна строка JSDoc в закрытых областях
оформлена двумя способами: без точки — `common`, `ui`, `layouts-blocks`, `text-editor`,
`builder/core`, `builder/canvas`, `builder/shell` (469 строк), с точкой — `render`,

### Ревью Codex, раунд 1 (gpt-5.6-sol high, свободное, 11 мин 34 с)

Двенадцать пунктов сверх записанных мной 15.1–15.11. Подтвердились все двенадцать (находки

в этом же этапе закрывал ложное утверждение**.

**Главный вывод раунда — про замену ложного обоснования.** Находка 15.3 сняла неверное «точечная
мутация не оповещает подписчиков» и поставила взамен «список и статус меняются вместе, иначе
получился бы кадр со свежим списком под прежним статусом». Ревью показало, что и это неверно:
`upsertUser`/`removeUser` меняют только `users`, `catch` — только `status`, а синхронные мутации
Vue рендерит пакетно, так что промежуточного кадра не бывает вовсе. То есть **опровергнув
утверждение, я поставил на его место второе непроверенное** — и прошло оно и гейт, и редактуру.
Правило на этапы 16–19: замена ложной причины проверяется тем же способом, каким было
опровергнуто прежнее; если проверяемой причины нет, комментарий описывает практику и прямо
говорит, чего причиной он НЕ является.

Вторая закономерность — **перенос из `<style>` без проверки тащит ошибку дальше**. Утверждение
«роль, статус и действия уходят на вторую строку целой группой» переехало в шапку дословно, и
замер его опроверг: при сужении строки хвостовые ячейки отрываются по одной (действия на 800 px,
статус на 700, роль на 520). Правило этапа 14 («проверять утверждение перед переносом») в этом
этапе я применил к содержательным решениям и не применил к «мелкой» верстке.

Третье: из двенадцати находок **пять — ошибки факта старше перевода** (403 как отсутствие
раздела, авторство и журналы у неизменяемого логина, «занят весь раздел», группа переноса, `>=`
против «выше»), одна — моя собственная (замена рационала), четыре — дубли рационала и оборотов.
Соотношение то же, что в этапе 14: чужих ошибок больше, чем своих.

Отдельно стоит записать процедурный успех: **претензии к регистру ревью отклонило само**. Слово

одной фразе промпта («претензии к регистру проверяй грепом по закрытым областям, а не на вкус»).

Найденное перепроверялось на своей стороне целиком: два пункта — экспериментом (замер переноса
ячеек в браузере, чтение хвоста ветки обрыва по коду), остальные — по коду и схеме. Ни один не
пришлось отклонить, но два уточнены при записи: авторство опровергается не только схемой, а и

### Находка, которую дал не греп, а чтение вычислимого выражения

`TheBuilderSessionError` дважды объяснял перенос фокуса тем, что рабочая область «под
inert». `inert` вешается по `isBuilderLocked`, а тот вычисляется как
`!sessionError.value && (…)` — то есть при показанном экране ошибки он ложен, и `inert`
не стоит **нигде**. Экран перекрывает рабочую область только для указателя; Tab уходит
за него, а `isSessionReady` там ложен, и всё набранное автосейв отклоняет молча. Это
ровно та потеря, ради которой барьер и делался, — и комментарий блокировщика описывает
её как закрытую. Текст обоих комментариев переписан на настоящую причину (экран лёг
поверх поля с фокусом), сама дыра записана находкой 19.5; заодно из блока над
`isBuilderLocked` убрано обещание, что экран ошибки «перекрывает рабочую область», —
теперь там сказано, что перекрывает он её для указателя.

**Вывод раунда.** Обе принятые находки — утверждения, **опровергаемые файлом, на который
