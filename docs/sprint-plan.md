# Спринт: ссылки, медиа, адаптивы, учётки, шаблоны

## Контекст

Семь пунктов от владельца по итогам эксплуатации билдера. Три из них — реальные баги
(канвас врёт про раскладку, published режет десктоп, шаблоны нарисованы но не существуют),
два — недостающие фичи в готовых модулях (ссылки в редакторе, категории/оптимизация медиа),
два — новая функциональность (редактор адаптивов, управление учётками).

Решения владельца, принятые при планировании:

- **Адаптивы**: произвольный набор устройств, но `desktop` и `mobile` обязательны, всего
  не более 4, у каждого — выбор иконки. Плюс per-page параметры.
- **Учётки**: создание пользователей, роли, смена паролей; всё выключается флагом конфига.
  Keycloak — только концепция и сбор информации в бэклог, но задел учесть в абстракции.
- **Шаблоны**: любую страницу можно дополнительно сохранить как шаблон (копия становится
  шаблоном). Загрузка из JSON — не обязательна.
- **Порядок**: малые фиксы → макеты → крупное.

Схема БД правится **в `migrations/0001_init.sql`** (не новым файлом): правка SQL → тот же
DDL руками в живую БД → пересчёт строки в `bricks_schema_migrations` → 0 pending.

### 5.1 SCSS-миксины для авторов брик-компонентов

Отдельный кусок работы, который спринт до сих пор не покрывал: разработчик проекта-потребителя
пишет свой `*.brick.vue` и не имеет способа сделать его адаптивным. Его media query
вычисляется по ширине окна, а канвас билдера — лист фиксированной ширины **внутри** окна
другой ширины, поэтому в билдере брик не перестраивается. В прошлой версии билдера это
закрывал проектный `respond-to`, эмитивший вторую ветку под селекторы канваса.

- **Развязка понятий, на которой всё держится**: брейкпоинт автора брика («уже 768 — в одну
  колонку») и ступень набора страницы («у этой страницы есть ноутбук») — разные вещи, и
  связывать их не нужно. Кто хочет следовать именно набору страницы — объявляет
  `responsiveCssVars` в `*.brick.ts` и получает значения per-device из схемы.
- **Механика миксина — две ветки, без style queries**:
    - `@media` для окна, огороженный `:where(:not(.bricks-canvas *))` (тот же guard, что уже
      генерирует `useBricksStyles`), — работает и на published, и на обычной странице
      потребителя вне билдера;
    - `@container bricks` для канваса — `.bricks-canvas` уже объявлен контейнером
      (`container-type: inline-size; container-name: bricks`), а `transform: scale()` на
      размер контейнера не влияет, поэтому лист отдаёт свою честную ширину.
      Поддержка container queries — Chrome 105 / Safari 16 / Firefox 110, в
      `> 0.2% and not dead` попадает целиком.
- **Состав API**: `bricks-up`, `bricks-down`, `bricks-between`, `bricks-only` плюс хелперы
  видимости поверх них (аналог прежнего `device-is`). Диапазон канвасных ступеней миксин
  считает по карте сам — в прежнем `respond-to` это было выписано руками через `@if`.
- **Перекрытие дефолта — опцией модуля `bricks.devices`** (решение владельца). Карта в
  миксинах объявляется через `!default`, модуль на `setup` резолвит опцию поверх константы
  `devices.ts` и пишет в `buildDir` файл вида

    ```scss
    @forward 'nuxt-bricks/scss/mixins' with (
        $devices: (
            mobile: 375,
            tablet: 900,
            desktop: 1600,
        )
    );
    ```

    Та же резолвнутая опция уходит в рантайм, поэтому канвас, контейнеры и пороги published
    считаются по тем же числам, что и миксины: одна ручка на обе стороны вместо прежних
    `bricks.breakpoints` + `device.breakpoints`. Прямой SCSS-путь
    (`@use 'nuxt-bricks/scss/mixins' with ($devices: $my-breakpoints)`) остаётся рабочим —
    он ничего не стоит и пригодится проекту, у которого уже есть своя сетка брейкпоинтов,
    но тогда числа расходятся с рантаймом и это ответственность потребителя.

- **Доставка**: alias `#bricks-scss` на сгенерированный файл; в SFC пишется явный
  `@use '#bricks-scss' as *`. Автоинъекции через `additionalData` не делаем: у потребителя
  это строка, и слияние затёрло бы его собственную.
- **Сборка пакета**: mkdist партиалы `_*.scss` в `dist` не кладёт вовсе, а не-партиалы
  компилирует в `.css` — то есть при нынешнем `build.config.ts` миксины до потребителя не
  доедут ни в каком виде. Нужна отдельная entry, копирующая `assets/scss/public/**` как
  исходники (mkdist без sass-лоадера копирует файл как есть), плюс сабпас в `exports`.
  Потребителю понадобится `sass` — он и так есть, раз пишет scss в SFC.
- **Попутно**: `BlockText` (п. 1.2) сегодня использует голый `@container` без второй ветки —
  ровно та половина механизма, из-за которой на published текст всегда 1.4rem. После
  миксинов у встроенных блоков и брикок потребителя механизм становится общим.
- Тесты: SCSS-карта совпадает с константой `devices.ts`; smoke — брик с миксином
  перестраивается и на канвасе (переключение вьюпорта), и на published (изменение окна).
- **Дополнительно почистить рассинхрон**: `BlockSlider.vue:134-144,394,398` —
  hardcoded 768/1024 вне конфига (свитч на 1024, когда остальной адаптив на 1600).
- UI: модалка создания страницы + настройки страницы в билдере, по макету.
- Тесты: расширить `test/layouts-blocks/responsiveLayoutCss.spec.ts` и
  `test/common/deviceVisibility.spec.ts` на произвольный набор устройств.
