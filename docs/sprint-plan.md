## Контекст

Семь пунктов от владельца по итогам эксплуатации билдера. Три из них — реальные баги
(канвас врёт про раскладку, published режет десктоп, шаблоны нарисованы но не существуют),

два — новая функциональность (редактор адаптивов, управление учётками).

Решения владельца, принятые при планировании:

- **Шаблоны**: любую страницу можно дополнительно сохранить как шаблон (копия становится
  шаблоном). Загрузка из JSON — не обязательна.
- **Порядок**: малые фиксы → макеты → крупное.

Схема БД правится **в `migrations/0001_init.sql`** (не новым файлом): правка SQL → тот же
DDL руками в живую БД → пересчёт строки в `bricks_schema_migrations` → 0 pending.

## Фаза 3 — п.7 Шаблоны

Фаза закрыта 19.08.2026. Что сделано — в README документации билдера
(`documentation/docs/guide/ru/07-publishing.md`, раздел «Шаблоны») и в контракте
внешнего backend'а (`docs/external-backend-contract.md`, раздел «Шаблоны
страниц»). Решения, принятые по ходу и отличающиеся от макета:

- **Превью шаблона — свой файл, копия кадра страницы**, а не ссылка на этот кадр:
  кадры страницы живут по её keep-list'у (страница + версии), и ссылка из шаблона
  той уборке невидима — первое же сохранение оставило бы карточку с битой
  картинкой. Копия делается серверно, best-effort; ключ `template-<uuid>.webp` в
  том же namespace, но под именем, которого уборка страниц не перечисляет.
- **Из билдера миниатюрой становится кадр последнего сохранения**, а не свежий
  снимок канваса (макет предполагал съёмку заново): своя ручка загрузки и свой
  namespace ключей ради вторичного артефакта того не стоят. Модалка говорит об
  этом подписью, поэтому расхождение картинки с содержимым не читается как
  поломка.
- **Появился PATCH подписи шаблона** (карандаш на карточке из макета): без него
  опечатку в имени нельзя исправить ничем, кроме удаления и повторного
  сохранения. Содержимое отпечатка ручка не обновляет.
- **Добавлен point-lookup `GET /templates/:id`**: сводка списка схему не несёт, а
  создание страницы из шаблона её требует. Содержимое читается при ВЫБОРЕ шаблона,
  а не при сабмите, — иначе набор устройств и оформление приезжали бы уже после
  подтверждения формы.

## Проверки

По каждой фазе (выбор по области изменения, как в `CLAUDE.md`):

- `.ts` / `.vue`: `npm run type-check`, `npx oxlint <файлы>`
- стили: `npx stylelint <файлы>`
- логика: `npx vitest run <спека>`
- границы модулей: `npm run deps:check` (обязательно для фазы 3 — новые
  server↔client связи)
- широкое: `npm run lint:check`, `npm test`, затем `npm run dev:build`
