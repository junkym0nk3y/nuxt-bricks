# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [семантическому версионированию](https://semver.org/lang/ru/).

Записи попадают в раздел «Не выпущено», а при выпуске переезжают под заголовок
версии вместе с датой. До версии `1.0.0` обратная совместимость не
гарантируется: минорный выпуск может менять публичный контракт модуля.

## Не выпущено

## [0.0.4] — 2026-11-12

### Добавлено

- Переключатель «Опубликована» в настройках публикации редактора — та же
  карточка, что в панели страницы на дашборде: переключатель, ссылка на
  страницу и копирование. Флаг пишется на сервер сразу, отдельным PATCH, как на
  дашборде, и публикует последнюю сохранённую версию страницы. Форма публикации
  получает новый флаг вместе со списком, поэтому следующее «Сохранить»
  публикацию не откатывает. На время записи «Сохранить» и поля панели
  заблокированы — переключение не идёт параллельно с сохранением. Флаг формы
  следует за строкой списка: если PATCH оборвался по таймауту, а сервер его
  применил, перечитанный список возвращает форме новый флаг.

### Изменено

- Строка списка страниц на дашборде — всегда три строки: название, адрес,
  описание. Раньше адрес делил строку с названием и при коротком названии
  вставал рядом с ним, а при длинном — под ним; строки одного списка не
  совпадали по высоте элементов.
- Ссылка на страницу в панели страницы — кликабельная, открывается в новой
  вкладке, и строится из сохранённого адреса страницы, а не из полей формы:
  адрес, набранный, но не сохранённый, ведёт в никуда.

### Исправлено

- Адрес страницы в панели страницы учитывает `app.baseURL`: приложение под
  префиксом (`/landings/`) показывало и копировало адрес без префикса, то есть
  ссылку на чужую страницу корня домена. Схема ссылки берётся из адреса билдера,
  а не всегда `https`.
- Флаг публикации больше не считается несохранённой правкой черновика: его
  пишет на сервер сам переключатель. Восстановленный черновик оставляет флаг
  формы (раньше возвращал старое значение, и следующее сохранение отправляло
  его на сервер), а черновик, отличающийся от сохранённой страницы только
  флагом, не предлагается к восстановлению. Неудачное сохранение возвращает
  форме серверный флаг, а не значение до запроса: после конфликта ревизий
  страница, которую снял с публикации другой редактор, больше не публикуется
  обратно следующим сохранением.
- Превью больше не сдвигает страницу вниз под плашку «Режим превью»: плашка
  висит поверх, отступ сверху под неё убран, и превью совпадает с
  опубликованной страницей.

## [0.0.3] — 2026-11-10

### Добавлено

- Опция `s3.publicUrl` (`NUXT_BRICKS_S3_PUBLIC_URL`) — публичный адрес объектов
  хранилища отдельно от API-адреса. Ссылки на загруженные файлы строятся как
  `<publicUrl>/<ключ>` вместо `<endpoint>/<bucket>/<ключ>`. Нужна там, где
  хранилище не отдаёт анонимное чтение по API-адресу: Selectel на такой запрос
  отвечает 403 даже для объекта с `public-read` и отдаёт его только с домена
  бакета, так что файл загружался, а ссылка на него не открывалась. Своими для
  удаления и медиа-прокси считаются только ссылки от `publicUrl`. Значение
  проверяется при старте адаптера: абсолютный http(s)-адрес без учётных данных,
  `?` и `#`.

### Исправлено

- Кука сессии `bricks-session` и куки настроек билдера (`bricks-dark-mode`,
  `bricks-locale`) ставятся на путь `app.baseURL`, а не на корень домена.
  Приложение под префиксом рядом с другим сайтом (например, `/landings/` на
  общем домене) отправляло токен сессии редактора с каждым запросом к этому
  сайту. Без `app.baseURL` путь прежний — `/`. Куки, выданные раньше на `/`,
  браузер хранит отдельно от новых до их истечения: установке, которая уже
  работала под префиксом, — выйти из билдера и удалить их в браузере.

## [0.0.2] — 2026-11-10

### Исправлено

- Канвас билдера рисует лист устройства с нестандартной rem-базой
  (`devices[].remBase`, например `0.6944vw`) так же, как опубликованная
  страница. Компенсация rem раньше входила в `transform` листа: лист сжимался
  целиком, а его раскладка оставалась шириной `width / 10` rem — у laptop
  1024px это 102.4rem вместо 144rem страницы, и вёрстка ломалась только в
  редакторе. Теперь контент внутри листа раскладывается на ширину страницы в rem
  и масштабируется до листа, а сам лист остаётся шириной устройства, и container
  queries (`bricks-up(...)`) срабатывают по нему, как раньше. То же — у листов
  Figma-режима.

## [0.0.1] — 2026-10-22

Первый публичный выпуск.

### Добавлено

- Nuxt-модуль с дашбордом страниц, drag-and-drop билдером, предпросмотром и
  рендером опубликованных страниц.
- Layout-блоки (Section, Grid, Flex, Slider, Space, Text, Media, Svg, Accordion)
  и подключение пользовательских brick-компонентов из каталога потребителя.
- Адаптив: набор устройств настраивается для проекта и для отдельной страницы,
  свойства блоков и их видимость задаются по устройствам.
- Backend данных в двух режимах: встроенный PostgreSQL с миграциями и внешний
  HTTP backend по документированному контракту.
- Авторизация в двух режимах: Basic Auth и учётки в PostgreSQL с ролями
  `admin` / `editor` / `viewer`, управлением учётками и своим профилем.
- Медиа: загрузка в S3-совместимое хранилище, медиатека с категориями,
  оптимизация изображений и генерация вариантов.
- Версии страниц с восстановлением, шаблоны страниц, код страницы в `head` и
  `body`, data sources опубликованных страниц.
- CLI миграций `bricks-migrate` (`status`, `migrate`), защита от checksum drift.
- Интерфейс на русском и английском, русский по умолчанию. Встроенная
  документация на русском.
- Публичный SCSS-миксин API брейкпоинтов (`nuxt-bricks/scss/mixins`) и
  подключаемый санитайзер (`nuxt-bricks/sanitize`).
